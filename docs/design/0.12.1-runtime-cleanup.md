# 0.12.1 runtime cleanup

## Scope

This cleanup preserves the 0.12 runtime ownership model, declaration snapshot
semantics, and persisted allocation ledger. It also makes one deliberate
pre-1.0 public API hard cut: policies passed to runtime bootstrap now implement
`RuntimeBootstrapPolicy` and provide an explicit semantic identity.

## Module boundaries

The runtime implementation is now divided by responsibility:

- `runtime/mod.rs` owns `MemoryRuntime<M>`, its lifecycle, bootstrap, committed
  capability, and memory opening.
- `runtime/policy.rs` adapts linked declaration authority and caller policy to
  runtime validation.
- `runtime/diagnostics.rs` reads lifecycle, ledger recovery, and live memory
  sizes from the same runtime owner.
- `runtime/default.rs` contains the one thread-local default runtime and its
  thin convenience entry points.
- `runtime/error.rs` contains the public typed runtime errors.
- `runtime/tests.rs` contains runtime unit tests without expanding production
  modules.

Declaration-registry tests likewise live in `registry/tests.rs`, separate from
the registration and sealing implementation.

## Preserved invariants

- One `MemoryRuntime<M>` owns all state derived from one backing memory.
- Only linked declaration registration and its immutable sealed snapshot are
  process-global.
- Capability publication still follows successful ledger persistence.
- Repeated bootstrap of the same runtime remains idempotent when its sealed
  declaration snapshot and explicit policy identity match.
- The default runtime remains thread-local on native targets and
  canister-lifetime on single-threaded IC Wasm.
- No reset API, compatibility shim, fallback state, or second runtime
  implementation is introduced.
- Stable-cell and protected allocation-ledger bytes are unchanged.

## Follow-up hardening

- `RuntimeBootstrapPolicy` now supplies a semantic identity. A successful
  runtime stores that identity and its sealed snapshot beside the committed
  capability; repeated calls with either mismatch return typed bootstrap
  errors.
- Constructor deferral records late-registration failure in declaration
  registry state, so macro-generated constructors no longer discard a fallible
  result.
- Deferred constructor failures are part of the registry's single lifecycle:

  ```text
  Open
    -> Sealing { owner, deferred_error }
         -> Sealed(SealedDeclarationSnapshot)
         -> Failed(StaticMemoryDeclarationError)
  ```

  This removes the separate failure slot that could disagree with lifecycle
  state, preserves the first canonical failure, and keeps late registration,
  reentrancy, poisoning, and invalid declarations as distinct typed errors.
- Snapshot publication reuses one registry guard for final construction and
  lifecycle publication.
- The committed-capability compile-fail test now targets the private
  persistence-confirmation boundary, avoiding rustc-version-specific missing
  item wording.
- A downstream-style integration bootstraps the default TLS runtime with a
  custom policy, repeats bootstrap with the same semantic identity, verifies
  that the generation does not advance, and opens the committed memory.

## CI regression gates

- Rust 1.97.1 is the pinned development and primary CI toolchain.
- Rust 1.85.0 remains the declared MSRV with a dedicated all-target check.
- CI runs the exact default-runtime regression and the complete suite with
  `--test-threads=1`.
- A `cdylib` example exercises bootstrap and open-memory code on
  `wasm32-unknown-unknown`. The reproducible `wasm-size` profile uses size
  optimization, fat LTO, one codegen unit, aborting panics, and stripped
  symbols. CI enforces a 240,000-byte raw, non-gzipped artifact budget.

The current Rust 1.97.1 probe is 233,565 bytes, 1,085 bytes (+0.47%) above the
232,480-byte 0.12.0 result. Fifteen local release runs measured a 5,141,205 ns
median bootstrap; seven runs measured a 61 ns median open. The 0.12.0
comparison was 5,221,306 ns and 67 ns. These small, noisy variations do not
indicate a material size or hot-path regression from the cleanup and bootstrap
binding.

The repository's maintainer/whitepaper toolchain is outside this patch's
requested validation scope and was not run.
