# 0.12.3 policy and diagnostics hardening

## Scope

This release completes the remaining review feedback after the explicit
`MemoryRuntime<M>` redesign and fallible construction work. It makes policy
identity a bounded value, makes doctor validation policy-aware, preserves
per-slot size failures, and separates core from diagnostics Wasm size budgets.

The changes are one pre-1.0 API and diagnostic-shape hard cut. There are no
compatibility aliases or dual report shapes.

## Policy identity

`RuntimeBootstrapPolicy` now constructs:

```rust,ignore
fn runtime_bootstrap_identity(
    &self,
) -> Result<PolicyIdentity, PolicyIdentityError>;
```

`PolicyIdentity` contains:

- a printable ASCII policy-family name bounded to 256 bytes;
- a nonzero semantic version; and
- an optional caller-computed 32-byte configuration digest.

The version changes when policy semantics change. Configuration-dependent
policies attach a digest of their effective configuration. ic-memory does not
choose the digest algorithm because the integration owns the configuration
meaning.

Construction and deserialization both validate the identity invariants.
Bootstrap rejects an invalid identity before recovery or persistence. A
repeated bootstrap compares the complete identity, including the digest, with
the identity bound by the successful call.

This identity is intentionally in-memory runtime lifecycle and diagnostic
state. It is not persisted in the allocation ledger and is not upgrade audit
history. Persisting it through runtime-fingerprint history would be a durable
format and operational-semantics decision and is outside this release.

## Declaration fingerprint

Sealing computes one `SealedDeclarationFingerprint` from canonical
declarations, linked-code authorities, and effective range authority. The
version-1 value applies FNV-1a 64 to CBOR serialization of that canonically
ordered material.

The fingerprint is:

- deterministic across constructor and registration ordering;
- versioned so its calculation can evolve explicitly;
- shared by every clone of the sealed snapshot; and
- diagnostic comparison metadata only.

It is not persisted allocation authority, a cryptographic digest, or an
adversarial integrity proof. Runtime idempotence continues to require the same
sealed snapshot object; it does not weaken authority to a hash comparison.

## Policy-aware doctor reports

The explicit API is now:

```rust,ignore
runtime.doctor_report(&declarations, &policy)
```

The default convenience API has two intentional entry points:

- `default_memory_manager_doctor_report()` evaluates the built-in policy;
- `default_memory_manager_doctor_report_with_policy(&policy)` evaluates an
  integration policy.

`MemoryRuntimeDoctorReport` includes:

- the tested `PolicyIdentity` or its typed validation failure;
- the tested sealed-declaration fingerprint;
- the policy/declaration binding established by successful bootstrap, if any;
- a typed comparison between tested and established binding; and
- declaration validation under the same caller-supplied policy.

An invalid identity prevents policy validation and is reported as
`DiagnosticCode::PolicyIdentity`. An unbootstrapped runtime has no established
binding. A mismatched tested binding is reported independently from whether the
tested policy accepts the declarations.

## Per-slot memory sizes

Doctor ledger records now hold:

```rust,ignore
Option<DiagnosticMemorySizeOutcome>
```

The outcome is either `Measured(DiagnosticMemorySize)` or
`Failed(DiagnosticFailure)`. One malformed slot therefore does not discard
successful live-size measurements for every other allocation.

The strict post-bootstrap `diagnostic_export()` API continues to fail if a
committed slot cannot be interpreted as a usable `MemoryManager` ID. The
per-slot behavior replaces only the former lossy doctor-report projection.

## Error and ownership model

Policy identity and declaration fingerprints are stored in the
`Bootstrapped` lifecycle binding belonging to one `MemoryRuntime<M>`.
Diagnostics read that same binding and the same runtime's memory manager.
Nothing in this release introduces process-global runtime state.

Invalid identity, bootstrap-binding mismatch, policy rejection, stable-cell
corruption, protected recovery failure, and per-slot size failure remain
distinct typed states.

## Persisted-format assessment

No persisted allocation-ledger format changes are required. This release does
not modify:

- stable-cell framing;
- protected commit slots or checksums;
- ledger payload format marker or version;
- allocation, generation, or schema-history DTOs; or
- durable codec fixtures.

Doctor DTOs are operator-facing diagnostic exports, not persisted open
authority. Their hard-cut shape changes do not add a legacy decoder.

## Wasm size tiers

CI now builds two stripped, uncompressed probes under the same `wasm-size`
profile:

| Tier | Reachable paths | Rust 1.97.1 bytes | Budget |
| --- | --- | ---: | ---: |
| Core | default bootstrap and committed open | 239,150 | 245,000 |
| Diagnostics | default bootstrap, doctor/export, CBOR serialization | 281,858 | 290,000 |

Separate gates prevent optional operator diagnostics growth from hiding growth
in the bootstrap/open integration path. They are representative reachability
probes, not whole-canister budgets.

## Tests

Focused tests cover:

- name, version, length, ASCII, control-character, and digest identity rules;
- revalidation of malformed deserialized identities;
- repeat-bootstrap version and configuration-digest mismatches;
- invalid identity leaving a runtime unbootstrapped;
- doctor validation through a rejecting custom policy;
- matching, absent, and mismatched runtime bindings;
- deterministic declaration fingerprints independent of registration order;
- fingerprint changes when linked declaration authority changes;
- per-slot measurement success and failure in the same doctor export; and
- the custom-policy default TLS doctor entry point.

## Remaining risks

- Policy configuration digests are only as stable and complete as the
  integration's canonicalization and hash choice.
- The declaration fingerprint is deliberately non-cryptographic and must not
  become authorization or persisted identity by convention.
- Adding fields and explicit result variants increases diagnostics reachability
  size; the separate diagnostics budget makes that cost visible.
- Whole-canister reachability depends on downstream code and must still be
  measured by integrators.
