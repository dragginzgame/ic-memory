## [0.46.0] - 2026-10-17

[#118 — Enforce exclusive allocation leases and narrow substrate exports](https://github.com/dragginzgame/ic-memory/issues/118)
owns this cut and its delivery/consumer acceptance.

**Breaking runtime ownership:** `RuntimeMemory` is a non-cloneable allocation
lease. A runtime refuses a second live open with `RuntimeOpenError::AlreadyOpen
{ id }`, without reading or mutating backing memory. Dropping the handle releases
its slot. Collections own the lease until dropped or transferring the same
handle onward; failed construction and ordinary native unwinding also release it.
Warm bootstrap, authority verification and diagnostics do not reset leases.
A fixed 32-byte bitmap shared with the runtime's existing growth owner tracks
live slots without allocating a separate object for each lease.

Hosts retain one runtime's exclusive backing custody. They must not construct
another runtime or manager, or perform raw aliased IO, until the runtime and all
its handles are dropped. Handles can outlive the runtime; dropping just the
runtime is insufficient. Generic backing aliases cannot be detected, and these
APIs do not sandbox arbitrary linked code. See [the custody contract](../../SAFETY.md#runtime-and-lease-custody).

**Breaking exports:** the blanket substrate re-export is removed. Use root
`Memory`, `DefaultMemoryImpl` and `VectorMemory` for host backing setup. Production
collection integrations belong in IC Storage's governed facade and consume
leases. Memory's internal manager/ledger and substrate qualification stay here;
no Memory-to-Storage dependency is introduced. A log needs distinct index/data
allocations. Coordinate downstream adoption against the published Memory API.

Lease state is volatile. The existing ICMSNAP1 ledger/Cell/manager formats, IDs,
checksums and mappings are unchanged; this API cut requires no reset, conversion
or new retained-image disposition. Existing 0.45 images remain the current format.

## Policy and recovery API

**Breaking policy API/JSON:** `PolicyIdentity::new` takes one `[u8; 32]` and is
infallible. The policy callback returns `PolicyIdentity` directly. Hosts prepare
fallible configuration and own names, versions and token derivation. Every byte
value is accepted, including zero; token equality binds semantics/configuration,
not authentication. Change the token when admission or allocation policy changes.
Requests and the pool retain their separate exact binding; no duplicate hash of
those inputs is required. The token is not persisted and introduces no hashing
algorithm or dependency in Memory.

Remove the old identity-name/version/digest accessors, identity error and identity
input decoder. Use `as_bytes()` for the token. Diagnostic binding identities are
32-element byte arrays; `MemoryRuntimeDoctorReport::tested_policy_identity` is
the direct token rather than a Result wrapper. The unreachable identity-failure
bootstrap variant and diagnostic category are removed. Allocation/admission
errors and warm mismatch refusal keep their existing roles.

**Breaking ledger API:** `RecoveredLedger` is internal. `AllocationLedger`,
`LedgerCommitStore` and bounded raw commit-store readers are available only under
`testing` with `test-support`; passive `DiagnosticExport::from_ledger` construction
also requires that feature. Production callers use `diagnostic_export`,
`commit_recovery_diagnostic` and `doctor_report` on their host-owned runtime.
Bounded Cell payload inspection remains public. Raw fixture decoding/constructing
DTOs does not establish recovery, durable publication or allocation authority.
The current durable readers, marker/checksum checks and exact-successor checks
remain internal and unchanged. No stored-format conversion is part of this cut.

## Release tooling

Release validation captures Cargo configuration once before its gate and reuses
that admitted observation in the receipt. This avoids a repeated environment,
configuration discovery and file-hashing pass. The post-validation comparison
still rejects configuration changes; preparation, publication and retry checks
retain their independent observations. There is no runtime or stored-format
change.
