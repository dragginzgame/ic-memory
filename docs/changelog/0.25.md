# Detailed notes for 0.25

## [0.25.14]

- Fix runtime memory bounds enforcement before upstream bucket-cache
  translation. Reads, raw reads and writes reject virtual slack and overflowing
  offset/length pairs before backing IO, regardless of cache state or build
  profile. A release-mode regression reproduces neighboring-allocation corruption
  against 0.25.13; the fix preserves that allocation and newly grown zeroes.
- Preallocate stable-cell record serialization with the existing exact size
  counter and canonical encoder. At 65,536 generations, matched native encoding
  peak heap falls from 23,591,104 to 11,795,632 bytes and reallocations fall from
  seven per call to zero. Current durable fixture bytes are unchanged.
- Avoid generation uniqueness-set allocations for strictly increasing history.
  Unordered input retains general validation and error precedence. The measured
  empty-allocation fixture eliminates 10,922 set allocations per validation at
  65,536 generations; allocation-key validation remains unchanged.
- Bound `DeclarationSnapshot` deserialization to 255 entries before decoding an
  excess entry. Mark `PendingBootstrapCommit` as `#[must_use]` to warn when the
  persistence/confirmation obligation is accidentally discarded, including after
  consuming the enclosing result.
- Add installed PocketIC 16 IO and upgrade qualification with a caller-owned
  server and an isolated host-only dependency graph. Verify invalid-IO traps,
  rollback of an earlier write, retained allocation IDs and bytes, failed upgrades
  after persistence or geometry conflict, and a successful same-contract retry.
- Record the bounds-check cost: cached byte IO adds 103–105 IC instructions per
  call; three existing raw Wasm probes grow by 329–347 bytes and the installed
  fixture by 390 bytes. No native encoding speedup, stable-memory saving or
  whole-bootstrap instruction improvement is claimed. Matched CSVs, reproduction
  commands and input/artifact identities are in the
  [qualification record](../runtime-io-qualification.md).
- Preserve valid IO, durable formats, allocation policy, production dependencies,
  toolchains and size budgets. Invalid IO now reliably refuses; oversized serde
  errors may arise earlier. Callers denying warnings must consume or explicitly
  discard pending commits.
- Release preparation now checks the numbered pending entry against the selected
  candidate. It rejects conflicting or repeated candidate identities without
  modifying finalized historical sections. Test command effects remain
  substituted; this change does not qualify a live release workflow.
- Dependency declarations now inherit their owning workspace catalogs without
  version or feature changes. The accepted isolated qualification workspace
  retains its own catalog and lockfile under the documented local exception.
- Add `make install-hooks` for the reviewed Shared Tooling pre-commit hook.
  It formats the exact selected index payload, rejects partial staging and
  preserves unrelated edits. `make fmt` and non-mutating `make fmt-check` cover
  both maintained workspaces with cargo-sort 2.1.4 and the pinned rustfmt.
  CI installs that formatter explicitly; metadata preparation checks formatting
  before packaging so release identity never depends on a hook repair. Existing
  clones activate the hook through the documented
  [developer setup](../host-support.md#developer-setup-and-formatting).
  `make test-hooks` exercises the actual formatting targets and staging isolation
  in disposable fixtures on every declared native CI host, without commits,
  tags, builds or network access.
  Hook setup resolves the physical checkout path first, so logical aliases such
  as macOS temporary paths do not produce a false repository-root refusal.

Focused qualification results and their source/host limits remain in the
[qualification record](../runtime-io-qualification.md). Full release gates,
native macOS and current Canic/IcyDB application graphs require separate evidence.
