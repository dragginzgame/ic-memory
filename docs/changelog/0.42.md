# 0.42 release notes

## [0.42.0] - 2026-10-15

**Breaking adapter API:** `StableCellLedgerRecord` is a decoded, serializable DTO
and no longer implements `ic_stable_structures::Storable`. Use `MemoryRuntime`
for allocation persistence and the fallible `decode_stable_cell_*` helpers for
read-only inspection. There is no public manual ledger publication replacement.
The runtime's bounded publication encoder and fallible readers are unchanged;
this cut changes neither the persisted Cell/ledger bytes nor recovery semantics
and requires no retained-data reset.

**Breaking diagnostics API:** per-ID allocation rows no longer carry the
always-null `payload_bytes` field. Remove it from report constructors and
consumer projections; collection owners must measure their own payload occupancy.
Capacity, slack, binding and conservation accounting retain their meaning.
`RecoveredLedger::physical_generation()` is also removed: use
`current_generation()` for the counter already checked against both stored
physical and logical values. Recovery still rejects a counter mismatch before
constructing the recovered proof. Neither removal changes persisted bytes.

Physical recovery diagnostics now use `CommitSnapshotDiagnostic` directly;
`CommitStoreDiagnostic` and its duplicated `current`/`recovery` fields are removed.
Match `Empty`, `Valid { generation }` or `Invalid { generation }` on the returned
value and on the optional `commit_recovery` fields in exports and doctor reports.
The serialized field carries that enum directly. Invalid generations remain
untrusted observations. Physical checksum success does not imply logical ledger
recovery success; decoding, integrity and counter-binding checks still run.

`BootstrapError` is removed. Bootstrap preparation is private to the runtime and
returns the existing `RuntimeBootstrapError` variants directly, preserving
validation, staging and ledger failure categories. Consumers naming the removed
type must use the runtime error; its ledger variant is `LedgerCommit`.
Persistence confirmation and allocation-open authority retain their ordering.

The release launcher now delegates workspace-version admission and literal
rendering to the existing Shared snapshot. Lock selection uses parsed TOML and
the canonical stable-version admission helper. Supported indentation, table
spacing and comments are preserved in scratch manifests. Invalid or ambiguous
selections and failed parser observations stop before cache preparation or helper
compilation. Scratch custody, explicit offline/network policy and release receipt
admission remain Memory-owned. The same Shared revision and payload bytes are
retained; the workspace-version reader is now an explicit snapshot entrypoint.

Validated declarations remain directly owned until persistence confirmation.
Published application capabilities share only their immutable declarations and
retain the committed generation; validation-only base metadata is discarded.
Governance declarations remain in the persisted ledger and are filtered before
sharing application authority. Capability clones remain cheap and immutable;
failed persistence still publishes no allocation authority.

Internal Cell fixtures now publish through that same bounded encoder. Native
allocation workloads construct valid ledger records through checked allocation
declarations rather than mirroring their JSON schema. Malformed-key workloads
serialize a valid current ledger and change only its key, preserving the current
slot shape and ensuring the measurement reaches its intended key bound. A normal
unit test covers the valid maximum-length key and the first excessive length.
Generic backing memory and Cell mechanics remain upstream in
`ic-stable-structures`; Memory owns its allocation-schema fixtures. Native
allocator extraction remains publication-gated under
[#93 — Adopt Testkit allocator measurement](https://github.com/dragginzgame/ic-memory/issues/93).

Sealing retains only canonical immutable requests. The diagnostic fingerprint is
computed on demand using the same algorithm and encoded input; repeated bootstrap
still compares complete canonical snapshot contents, pool and policy identity.
The public fingerprint, declaration and persisted ledger contracts are unchanged.
Repeated diagnostic calls recompute the hash rather than retaining a cache.

The earlier matched fingerprint probes against released 0.41.0 (`2c4a687`) save
1,837 raw Wasm bytes and 1,611 bytes with Binaryen 133 `-Oz` in the core probe.
All five probes shrink: 65–1,883 raw bytes and 84–1,698 optimized bytes. Both
sides used Rust 1.99.0's size profile, the same locked Build 0.6.0 / Host 0.19.0
graph and the optimizer's bulk-memory option. Those retained results describe
the fingerprint change before this adapter cleanup and the incoming Build 0.6.1
selection; they are not fresh evidence for the combined candidate. These are
probe sizes, not application-canister or IC instruction measurements. Artifacts
and logs remain under `target/qualification/cleanup0411/`.
