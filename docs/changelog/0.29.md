# Detailed notes for 0.29

## [0.29.0] - 2026-10-07

### Shared setup and governance

- **Breaking developer setup:** both host installation and offline checks now
  select the shared pinned jq/yq/ripgrep set. Refresh a jq/yq-only installation
  with `make install-host-tools` before validation. CI uses the same set and
  removes its separate apt/Homebrew ripgrep installation.
- Adopt the reviewed committed Shared Tooling 0.1.12 snapshot at
  `33c2a6f0018a94915f819ff219e270500ed5b73b`, including the shared maintenance
  policy and exact-commit GitHub CI helper. The local audit overlay identifies
  this snapshot accurately. Maintainer-owned commits, tags, pushes and broad-gate
  boundaries remain the approved local exceptions.
  [#17](https://github.com/dragginzgame/ic-memory/issues/17).
- Refresh the runner's recorded-destination checks and the snapshot verifier's
  independent hashing bootstrap. A changed checksum helper cannot approve a
  tampered snapshot. These are canonical shared exports, qualified separately
  from live release effects.
  [shared-tooling #25](https://github.com/dragginzgame/shared-tooling/issues/25),
  [shared-tooling #27](https://github.com/dragginzgame/shared-tooling/issues/27).
- Inspect a selected source with
  `GH_REPO=dragginzgame/ic-memory bash scripts/dev/gh-ci.sh --commit HEAD --all-workflows --limit 100`.
  The authenticated read-only listing is bounded; it does not certify complete
  workflow coverage or qualify uncommitted changes.

### Durable host metadata writes

- Replace the local generic atomic writer with `ic_host_fs::durable::write_bytes`.
  The host library owns sibling staging, collision handling, complete-file
  replacement and file/parent synchronization. Release intent, metadata ordering,
  receipts and recovery remain consumer-owned.
- Use the published split `ic-host-fs` and `ic-host-artifacts` 0.3.0 dependencies
  for filesystem hashing and digest identities, with unused features disabled.
  Remove the old host-tools monolith and its unused archive/Wasm parser graph.
- Qualify rollback and retry before publication and after complete replacement
  becomes visible. An error alone does not prove that publication had no effect;
  the adapter reconciles owned bytes against the same saved intent.
  [#16](https://github.com/dragginzgame/ic-memory/issues/16).

### Failed release-fixture diagnostics

- Keep consumer Make-adapter fixtures on failure and report their retained
  paths, matching the shared command and runner fixtures. Successful runs still
  remove their scratch directories.
- Keep Rust adapter fixtures during assertion unwinding. Save the existing
  serialized command state beside their receipts and artifacts; diagnostic
  write failure is reported without replacing the original panic.
- Cover retained validation receipts and command state during a simulated
  assertion failure, alongside successful cleanup. Release effects remain
  substituted.
- Route native CI fixtures into a dedicated runner temporary directory and
  upload failed fixtures, tool candidates, qualification evidence and setup/gate
  logs for 14 days. Upload MSRV compiler failures separately. Bash pipefail
  preserves command failures while logs are streamed.
  [#15](https://github.com/dragginzgame/ic-memory/issues/15).

The setup admission change requires the minor candidate. Library APIs, durable
memory formats, release receipts, Rust/MSRV pins and runtime qualification's
independent dependency graph retain their current contracts. Host-only dependency
selection changes in the root graph; no canister source changes.
