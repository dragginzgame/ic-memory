# 0.41 release notes

## [0.41.0]

**Breaking declaration API:** allocation declarations contain key, checked slot
and schema metadata. Remove the label argument from `AllocationDeclaration::new`
and use `memory_manager(key, id)` or
`memory_manager_with_schema(key, id, schema)`. Labeled/unlabeled variants and
label-specific errors are removed. Keep application display names outside the
allocation-governance contract; authority names retain their existing checks
([#114 — Remove unused allocation declaration labels](https://github.com/dragginzgame/ic-memory/issues/114)).

**Breaking durable and DTO contract:** `MemoryManagerSlot` serializes directly
as its numeric ID, retaining checked construction and rejection of the 255
sentinel. The logical `ICMEMLED` envelope uses the distinct `ICMN` discriminator
at version 1. The physical one-current-snapshot representation, checksum,
key-to-ID/tombstone rules and underlying collection layout remain unchanged,
but earlier logical ledger bytes are incompatible. All current wire fixtures
are replaced using the crate's encoder; no fallback reader or automatic reset
is provided
([#115 — Hard cut slot encoding to a checked numeric ID](https://github.com/dragginzgame/ic-memory/issues/115)).

Matched Memory probes shrink by 3,955–4,625 raw Wasm bytes and 3,648–4,277
bytes with Binaryen 133 `-Oz`, using Rust 1.99.0's size profile on both sides.
The slot fixture shrinks from 25 to 2 CBOR bytes (ID 100); removing the same
wrappers saves 23 bytes per encoded slot. These are probe/codec measurements,
not application-canister or IC instruction claims. The incoming Build 0.5.0 and
Host 0.18.6 selection is identical on both sides.

Before deployment on retained data, follow the
[current ledger disposition requirements](../current-ledger.md#hard-cut-and-retained-installations).
Do not clear the ledger while retaining untracked collection bytes. Canic's
constructor callers and consumer-owned adoption/retained-installation review are
tracked in [Canic #573 — Adopt Memory numeric slot and label API hard cut after publication](https://github.com/dragginzgame/canic/issues/573).
No retained installation is qualified by this source change.

Native release adapters delegate stable-version and Gregorian-date grammar to
the snapshot's pure Shared admission helper. Typed numeric output and exact
returned-date checks preserve the helper boundary; independent saved-source,
lock selection, receipt, metadata, increment, publication and recovery checks
remain local. Missing/refused/malformed helper output stops before preparation
and keeps prior evidence. The helper is a direct selection root; executable
payloads and tool pins remain unchanged. Rust u64 version admission stays
separate from the increment helper's signed arithmetic headroom
([#102 — Converge release version and date admission on Shared](https://github.com/dragginzgame/ic-memory/issues/102)).

The Shared Tooling snapshot selects committed source
`3bef3f2daec7f64f875397ed4d53d5b9e2e68a08` (0.15.0), with 113 payloads
under 81 selection roots, including direct native admission. The release runner and version increment
helper share canonical version/date admission; isolated consumer fixtures copy
that new companion. Memory retains its independent Rust receipt and recovery
checks. The adopted baseline replaces the separate older validation-policy
reference. Tool pins, installer inputs and managed build identities are unchanged;
no tool reinstall is needed. Only exported committed behavior is adopted, not
pending changes described in the producer's draft notes.

The native Host requirements remain in the 0.18 compatible line, matching
published Build 0.5.0's exposed process types. Selecting Host 0.19 directly while
Build selects 0.18 produces incompatible `OutputLimits` types at the Cargo
metadata boundary. The lock contains one 0.18.6 Host set. Coordinated Host 0.19
adoption waits for publication of
[Build PR #44 — Align public Host dependency types with 0.19](https://github.com/dragginzgame/ic-build/pull/44),
tracked by [Build #9 — Qualify consumers against the current exposed Host boundary](https://github.com/dragginzgame/ic-build/issues/9).

The selected native Host artifacts, filesystem and process packages are 0.18.6.
Compatible workspace requirements and the normal canister dependency graph stay
unchanged. Host 0.18.6 changes its contributor baseline rather than library Rust
source compared with 0.18.5. This adoption does not change the runtime server,
client or installed qualification contract
([#62 — Qualify native tooling and evidence](https://github.com/dragginzgame/ic-memory/issues/62)).

The independent installed-runtime qualification lock selects rustls 0.23.46,
addressing RUSTSEC-2026-0346 through RUSTSEC-2026-0349. Only that package's
version and checksum change. PocketIC remains 16.0.0, with the existing Testkit
0.25.4 / PocketIC 16.1.0 server pairing and independent Rust 1.88 floor. This is
a native test-client dependency; the library and its normal Wasm graph do not
depend on rustls
([#107 — Replace rustls 0.23.45](https://github.com/dragginzgame/ic-memory/issues/107)).

Native full-test jobs restore common Cargo tool builds and their managed source
cache using the existing Shared key derived from compiler, native environment,
runner image, selected pins and installer inputs. Normal setup and offline
admission always run after restoration; only an admitted main-branch setup saves
the cache. Restore/save are optional and bounded to three minutes, so a miss or
transport failure continues through ordinary setup. No prepared cache grants
qualification or skips a required test.

The full native job budget is 60 minutes on all three hosts, matching the existing
runtime budget. The former 30-minute limit repeatedly cancelled Intel tests after
cold tool preparation. All native, MSRV, installed-runtime, evidence and release
checks remain required. Hosted cache transport and warm macOS timings still need
current-source CI evidence
([#62 — Qualify native tooling and evidence](https://github.com/dragginzgame/ic-memory/issues/62)).
