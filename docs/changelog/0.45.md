# 0.45 release notes

## [0.45.0] - 2026-10-16

**Breaking allocation API/JSON:** the host pool accepts numeric exclusion IDs,
canonicalized into one fixed mask with governance always excluded. Use
`excluded_ids()` instead of the range accessor. Remove `MemoryManagerIdRange`,
`MemoryManagerRangeError` and the governance-range helper. Hosts expand their
configuration ranges at the boundary and group IDs for presentation. Binding
comparison still uses exact canonical eligibility; retained ledger claims and
sentinel rejection remain independent guards.

**Breaking schema/storage API:** remove `SchemaMetadata`, its errors, constructor
arguments and getters. Requests take `(authority, key)`; declarations take a key
and slot or use `memory_manager(key, id)`. Durable records contain key, slot and
state. Remove `RuntimeAdoptionError::DeclarationMetadataMismatch`; application
schema admission stays with its owner. Key/owner/slot and runtime-binding checks
remain. The maintainer approved retiring earlier images with fresh/reset memory.

The schema-free format uses the distinct `ICMSNAP1` marker. Current logical and
protected fixtures are regenerated by the canonical types/encoder while retaining
their keys, IDs, states and counters. Incompatible earlier markers fail closed.
There is no conversion, compatibility reader or automatic/deployed-canister
reset. Manager/Cell layout, numeric IDs, limits, dependencies and tools remain
unchanged. Consumers require the new minor and their own installation/data
disposition; see [the ledger contract](../current-ledger.md).

The runtime now stages, protects, persists and publishes authority in one owned
flow. The redundant pending-commit wrapper and manual confirmation step are
removed. The staged ledger is released before Cell encoding; authority is still
constructed only after persistence succeeds. Policy/error ordering, interruption
rollback and retry remain qualification requirements.

**Breaking policy API:** implement `validate_allocation(key, slot)` instead of
separate key and slot methods. Preserve any application-specific check/error
order inside that callback. It runs once per external allocation in doctor and
bootstrap, after host grants/pool checks and before historical claim validation.
Governance remains private; cold recovered admission and warm binding keep their
existing separate roles.

The Cell value now owns `current` directly. The internal one-field physical-store
wrapper and its serialized nesting are removed while marker/checksum admission,
exact successor checks, logical integrity and physical/logical counter binding
remain. The distinct `ICMSNAP1` identity also retires unpublished earlier 0.45
fixture bytes under the same approved fresh/reset disposition. No older reader,
conversion or deployed reset is added. See
[qualification](../current-ledger-qualification.md) for source-bound evidence.

## Output-only diagnostic reports

**Breaking diagnostic API:** reports and their diagnostic-only fields no longer
implement `Deserialize`. Applications requiring report input own that protocol
instead of treating runtime observations as a Memory input contract. Remaining
field names and values retain their encoding. Durable ledger types, checked
slots, host configuration and policy identities retain their existing decoders.
No stored-format change or additional retained-image retirement is introduced.

**Breaking report API/JSON:** `DiagnosticExport` contains only
`current_generation` and `records`. The doctor report retains physical recovery
status even when logical recovery fails; `commit_recovery_diagnostic()` remains
available separately. Both report anchor fields and the export's repeated
recovery status are removed. Use `MEMORY_MANAGER_LEDGER_ID` for the fixed anchor.
`DiagnosticExport::from_ledger` now takes only the ledger. Hosts own response
presentation; a successful runtime export has already passed physical and
logical recovery, while a passive DTO constructor certifies neither.

Resolution is the sole production constructor of its internal canonical output.
Sealing owns unique request keys; admission owns bounded, disjoint historical
selections; recovered integrity and the free-ID iterator establish placement.
The duplicate snapshot validator and its count/duplicate error variants are
removed from `DeclarationSnapshotError`. Raw key/slot admission, persisted-ledger
integrity, current host policy and historical collision checks remain independent.

Fixture setup no longer re-verifies the same authority immediately after its
successful single-request bootstrap. Remove `FixtureCellError::Authority` from
matches; other setup, payload and publication failures retain their behavior.

## Fixture-cell admission

Reconcile the bounded fixture work from [#105 — Share explicit fixture byte-cell construction](https://github.com/dragginzgame/ic-memory/pull/105)
and the fallible setup work from [#116 — Expose fallible fixture admission](https://github.com/dragginzgame/ic-memory/pull/116)
on the current explicit-runtime and direct-CBOR contract. `test-support` exposes
`FixtureCellError`, `FixtureCell::try_new`, bounded fresh/retained constructors,
`try_set` and admitted-memory transfer through `into_memory`. Existing `new` and
`set` retain their panic convention; the newly introduced bounded constructors
return typed errors. The helper retains only its Cell/handle and byte ceiling,
not the complete temporary bootstrap runtime.

Retained admission shares the ledger reader's existing header checks while
selecting the caller's byte ceiling; ledger bounds remain unchanged. Invalid
magic/version, impossible lengths and excessive payload sizes refuse before
Cell payload allocation/read or initialization. Fresh admission refuses occupied
allocations. Missing retained backing stays uninitialized. Oversized writes
refuse before mutation. Bootstrap can advance allocation-ledger metadata before
a later Cell refusal, and substrate IO/publication can still panic; this is not
a native crash-atomic transaction protocol or a new fallible IO engine.

The fixture-cell extension changes no storage format or dependencies. Callers retain codecs, initial
payload creation, retained-image disposition, work budgets and lifecycle checks.
The trusted `try_new` path is unbounded and suitable only for trusted images;
use `open_bounded` for an untrusted retained payload. Blob, Jobs and Auth must
select the published extension and qualify their own generated fixture images
and restore behavior; these producer checks do not establish consumer adoption.
