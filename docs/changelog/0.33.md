# Detailed notes for 0.33

## [0.33.4]

Refresh the immutable selection to committed Shared Tooling
`f77fcb1f623c2e5f14b3fbe96ef68d24e0c20771`, explicitly adding
`make/execution.mk` (88 selected files). The manifest now records the exact
commit's source `VERSION`, 0.2.8, separately from its revision. The upstream
commit label and pending notes say 0.2.9; they do not override the exported
version or prove a release. Refresh admits unannotated snapshots and rejects
malformed or duplicate version annotations before replacing consumer files.
[Snapshot qualification](../release-workflow-qualification.md#0334-shared-snapshot-version-metadata).

The inherited 0.2.8 Make admission resolves its probe
beside the reviewed include, independently of caller tooling roots, and checks
the running Make executable separately from argument-bearing recursive commands.
Release defaults and recipes remain shared; direct delivery, both-workspace
formatting and forced checkout-local routing/cache preparation remain local.
[#42](https://github.com/dragginzgame/ic-memory/issues/42),
[Shared #30](https://github.com/dragginzgame/shared-tooling/issues/30).

Use GNU Make 3.81-compatible target exports after reclassifying caller values,
preserving all four release entrypoints' forced policies. The previous combined
`override export` syntax failed while parsing even harmless developer commands.
[#45](https://github.com/dragginzgame/ic-memory/issues/45).
[Qualification and remaining admission limit](../release-workflow-qualification.md#0334-shared-028-make-admission).

Adopt published `ic-host-fs` and `ic-host-artifacts` 0.10.0. Receipt and archive
writers use the single `write_with(path, options, producer)` contract, preserving
replacement mode and permissions. Whole typed errors cross the release-tool
boundary, retaining producer I/O/serialization failures, cleanup evidence and
before/after-publication state. Fixture writers reuse the production boundary;
existing archive-copy checks inspect the preserved native error inside its typed
producer phase. No retired writer alias remains. Memory's public API, durable
formats and recovery behavior are unchanged, keeping this a compatible patch.
[#46](https://github.com/dragginzgame/ic-memory/issues/46).
[Host qualification](../release-workflow-qualification.md#0334-host-010-adoption).

## [0.33.1] - 2026-10-09

Failed release preparation leaves a metadata file in place when its bytes
already match the saved backup. This avoids replacing untouched files,
broadening private permissions and introducing unnecessary restoration errors.
Changed, owned replacements still roll back; concurrent edits, original errors,
actual restoration failures and qualification evidence remain preserved.
[#39](https://github.com/dragginzgame/ic-memory/issues/39).

[Qualification](../release-workflow-qualification.md#0331-untouched-metadata-rollback)

[Current package review](../release-workflow-qualification.md#0331-shared-023-and-host-092)

Correctly numbered pending root and detail entries can be finalized even when
their bodies contain no prose. Notes remain a maintenance obligation; their
content is no longer an executable release gate. Version/date agreement,
duplicate-entry refusal, source/index/payload admission and package receipts
remain enforced. Historical content keeps its original bytes, including a
missing terminal newline. [#40](https://github.com/dragginzgame/ic-memory/issues/40).
