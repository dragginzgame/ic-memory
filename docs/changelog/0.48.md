# 0.48 release notes

## [0.48.0]

### Fixture-only configuration decoding

`MemoryRequest`, `MemoryAuthority` and `MemoryAllocationPool` implement
`Deserialize` only with `test-support` (or within crate unit tests). Production
callers construct them through their checked Rust constructors. Serialization
remains available for diagnostic JSON and CBOR output.

Applications that accept external configuration own their input DTOs and pass
decoded fields through Memory's constructors; no new configuration layer is
introduced in Canic or another repository. Fixture decoding retains its checked
constructors, required fields, unknown-field rejection and invalid-input refusal.
Default-feature integration tests retain constructor admission and output-wire
coverage; decoding tests explicitly select `test-support`.

This is an API hard cut. Consumers deserializing these configuration types must
use application-owned DTOs, or enable `test-support` for fixtures. This
configuration API cut does not change ledger recovery or authority; the separate
stored-format cut below requires fresh/reset backing.

### One protected generation

The `ICMKEY01` snapshot stores generation once in its checksum-protected header.
Its opaque payload encodes only the bounded definite-length allocation-record
array. Recovery derives the in-memory logical generation from that checked
header; the physical/logical mismatch error is removed. Payload CBOR admission,
record limits, key/slot checks, ledger integrity, successor/overflow checks
and persistence before open authority remain enforced.

The maintainer explicitly retired ICMSNAP1 and pending ICMREC01 images for this
cut: use fresh/reset backing. There is no compatibility decoder, conversion, automatic
clearing or deployed-canister reset. The distinct marker rejects earlier images;
current payload and full-store fixtures are regenerated through the canonical
encoders. Numeric slot encoding, manager/Cell layouts and application collection
codecs are unchanged, but an old allocation-ledger image is no longer admitted.

### Fixture-only doctor reports

The combined doctor operation moves to
`testing::doctor_report(&runtime, &declarations, &pool, &policy)` and requires
`test-support`. Its report, binding, check, failure, code and stable-cell status
types move under `testing` with it. Fixture preflight retains its read-only
recovery, observation-before-callback ordering and partial-validation semantics;
it never replays recovered-admission preparation or certifies consumer readiness.

Production hosts use `diagnostic_export`, `commit_recovery_diagnostic`,
`memory_allocations` and `memory_allocation_summary`, and own response assembly
and error presentation. These core queries, corruption checks and bootstrap
admission remain in Memory. The production diagnostics size probe retires its
combined doctor export; it still measures ledger export and physical allocation
reporting. Its size change therefore includes removal of that fixture operation.

Consumers using the combined report must update the helper/type paths and enable
`test-support` for fixtures, or assemble their production response from the core
queries. Durable formats and allocation IDs are unchanged by this API cut.

### Sparse frozen fixture backing

`testing::memory_from_sparse_hex` expands ordered offset/hex runs into fresh
zero-filled VectorMemory under an explicit caller-selected page ceiling. It
checks address bounds and ASCII hex before backing allocation, retaining gaps,
trailing zeros and ordered overlaps. Typed failures identify page limits,
offending runs and substrate growth refusal.

This is fixture import only. Callers keep provenance, schema/JSON and payload
admission; no runtime is opened and no authority or stored-format conversion is
performed. Existing backing is never an input. The helper is behind
`test-support`, without new dependencies or changed allocation/storage behavior.
This integrates [PR #121 — Share bounded sparse memory image fixture loading](https://github.com/dragginzgame/ic-memory/pull/121)
with the released 0.47 fixture API. Jobs retains its local loader until producer
publication and consumer adoption.

### Bounded fixture Cells

Fixture Cells now expose only `create_bounded`, `open_bounded` and `try_set` for
construction and writes. Fresh/retained intent and byte ceilings are explicit;
there is no unbounded default or panic convenience route. Setup failures nest
`FixtureRuntimeError` under `FixtureCellError::Setup` rather than copying its
four categories and maintaining a conversion bridge. Source categories remain
available. Backing IO retains substrate panic behavior. Update callers and error
matches together; this API cut changes no stored Cell bytes or production Wasm.

### Consumer tooling qualification

The unchanged Shared 0.20.0 revision now selects 71 roots and 105 payloads,
retiring twelve generic regression fixtures and two unused derived helpers by
canonical ownership-checked refresh. Generic cases remain with Shared Tooling.
Memory keeps actual pin/catalog and prepared-tool admission, release/receipt and
rollback tests, Make and index-hook integration, failure archives, hosted
transport bindings and native CI reuse. The host installer fixture remains only
for a forced early failure whose original evidence must survive Memory's archive
round trip. Directly used Cargo cache-key and CI-inspection helpers remain explicit
roots. No product tests, release runner, full release gate or native host roster
are removed, and no measured CI speed-up is claimed.

### State-free permanent bindings

Allocation records now hold only a stable key and numeric slot. Production had
no retirement/reservation transition API; staging created or reasserted active
records. The lifecycle enum, retired-key error paths and fixture state inputs
are removed. Existing bindings are immutable during staging; checked new claims
append records. Every omitted binding still occupies its ID permanently, and
reintroduced keys retain their ID after current grant, pool and policy checks.
Application retirement and any rule forbidding reopening belong to the host and
storage owner. This deliberately removes durable retired-key rejection.

The `ICMKEY01` marker distinguishes this state-free shape from pending ICMREC01.
The maintainer explicitly retired both pending images and earlier published
formats: use fresh/reset backing. No old reader, automatic clearing, migration
or real canister reset is introduced. Current fixtures use only the bounded
canonical payload/store encoders; lifecycle-only fixtures are retired. The
manager/Cell substrate layouts, numeric ID domain and dependency graph remain
unchanged. Consumers must update the removed allocation-state API and diagnostic
field alongside their application-owned retained-data disposition.
