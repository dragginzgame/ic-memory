# 0.44 release notes

## [0.44.0]

The release-adapter fixture discovers Cargo before exporting its selection. A
failed lookup now retains its failure status instead of being masked by export,
and ShellCheck accepts the declaration. Release effects remain substituted
([#117 — Fix release-adapter Cargo discovery failing ShellCheck SC2155](https://github.com/dragginzgame/ic-memory/issues/117)).

Release configuration observation uses the selected IC Build API for Cargo
environment classification, ancestor/home discovery, include traversal and
same-read raw hashes. Memory retains compiler/wrapper refusal, environment value
labels, conservative custody of both root filenames and receipt/recovery checks.
Included configuration changes invalidate release evidence, and included compiler
overrides refuse preparation before release effects
([#110 — Adopt canonical Build Cargo environment observation after publication](https://github.com/dragginzgame/ic-memory/issues/110)).

Historical admission shares checked request names without constructing a
temporary request or allocating its discarded authority. Validation precedence,
poisoned attempts and recovered slot/schema selection are unchanged. The native
allocation measurement example uses the built-in generic policy; its policy
identity changes, so new measurements must identify that fixture revision.
Those request and native-measurement cleanups preserve the library API and wire format.

## Bootstrap staging

Validation and staging now own the same recovered ledger. Each declaration
runs key policy, slot policy and historical ownership checks once; the checked
claim index is applied only to the local staged ledger. Doctor uses the same
per-declaration checker without staging or replaying admission. Failure discards
local staging, and the protected store changes only after all checks succeed.
The runtime persists the Cell before publishing committed allocation authority.

**Breaking error API:** remove `AllocationStageError::StaleValidatedAllocations`,
`StableKeySlotConflict`, `SlotStableKeyConflict` and `RetiredAllocation`.
Historical claim failures retain their `AllocationValidationError` variants under
`RuntimeBootstrapError::Validation`. There is no separately transferable
validation proof that can be applied to another same-generation ledger.
Generation overflow and integrity staging errors remain. The staging cleanup
itself does not change durable ownership semantics.

## Admission examples

The runnable recovered-admission example retains an explicitly named known key,
checks its ID and marker after a cold reopen, and demonstrates a matching warm
bootstrap. It does not invent database control/journal grammar or lifecycle rules.
Those belong to IcyDB's existing `prepare_memory_bootstrap` implementation and
journal-admission integration tests; its current Memory adoption remains a
separate consumer qualification obligation.

## Direct ledger payload

**Breaking storage/API:** the protected snapshot now uses `ICMDIRCT` and contains
direct bounded ledger CBOR. Remove imports of `LEDGER_PAYLOAD_FORMAT_VERSION`
and `LedgerPayloadEnvelopeError`, and replace `LedgerCommitError::PayloadEnvelope`
handling with the applicable physical recovery or logical codec error. Unsupported
markers retain `DiagnosticCode::UnsupportedFormat` through the new
`CommitRecoveryError::UnsupportedFormat` variant. Marker/checksum validation,
logical ownership integrity, counter binding and byte/depth bounds remain.

The maintainer approved retirement of old images and fresh/reset memory for this
cut. Rebuild consumers together on the new minor. No earlier-format decoder,
converter, automatic reset or deployed-canister reset is included. The pinned
manager/Cell layout and numeric slot encoding are unchanged. Current fixtures
are replaced with direct logical CBOR and newly checksummed physical records.
See the [current qualification](../current-ledger-qualification.md#0440-direct-cbor-and-single-pass-staging-qualification)
for measured footprint and installed IO/upgrade evidence.

## Exact diagnostics and direct Cell values

Doctor and warm bootstrap now use the same exact binding checker over canonical
requests, allocation pool and policy identity. Remove `SealedDeclarationFingerprint`,
`SealedDeclarationSnapshot::fingerprint`, the diagnostic binding's
`declaration_fingerprint` and the doctor's `tested_declaration_fingerprint`.
The report still carries tested requests, policy/pool information and the binding
check result; diagnostics neither replay admission nor publish authority.

Replace `StableCellLedgerRecord` with the passive `LedgerCommitStore` DTO and
rename its readers to `decode_stable_cell_commit_store` and
`decode_stable_cell_commit_store_from_memory`. The Cell value encodes that store
directly, eliminating the serialized `store` wrapper. This is part of the same
maintainer-approved fresh/reset 0.44 storage cut. There is one current reader;
no old wrapper reader, conversion, reset or deployed-canister mutation is added.
Bounded publication, Cell-header admission, protected physical/logical recovery
and persistence before capability publication remain separate safeguards.
The commit-store fixture now also pins the Cell value; a duplicate fixture is removed.

## Fixture construction

The `test-support` feature supplies `testing::allocation_record(&declaration, state)`.
It constructs a passive record from checked fields; use `AllocationLedger::new`
to validate complete fixture ledgers. Remove fixture-only reservation/retirement
staging, `AllocationRetirement`, `AllocationReservationError` and
`AllocationRetirementError`. Production reserved/active/retired ownership,
tombstone conservation, admission and corruption checks remain supported.
Canic's projection tests can construct their desired record states directly;
its separate Memory adoption must select and qualify the published 0.44 API.

## Host-owned runtime and primary measurements

**Breaking runtime API:** remove the default singleton facade and
`RuntimeStateError`. The host constructs and retains one `MemoryRuntime`,
passes its policy and full snapshot to `bootstrap`, and injects runtime
references or opened handles into components. Canic and application code own
canister/thread storage and lifecycle. Component queries cannot initialize an
implicit runtime. Reentrant live growth accounting still returns
`RuntimeDiagnosticError::ReentrantAccess`.

**Breaking report API/JSON:** `DiagnosticMemorySize` stores Wasm pages; call
`bytes()` for byte extent. Allocation rows and binding summaries store bucket
counts and virtual extents; their byte/slack methods take measured bucket pages.
`MemoryAllocationSummary` retains geometry, counts, generation and extents;
byte totals are methods and fixed layout/read-budget facts are associated
constants. Detailed and summary paths retain checked physical measurements and
conservation. Canic owns its external presentation DTO and can expand values
there without making redundant values part of Memory's serialized contract.

Durable snapshot payloads use bounded CBOR byte strings only. JSON remains a
diagnostic output, with no array-to-payload input path. The byte-string CBOR
representation and its bounds are unchanged by this codec cleanup; it adds no
new storage reset requirement to the already approved 0.44 cut.

The selected Host 0.22.1 durable-write API now receives explicit replacement
options, preserving the helper's replacement mode and 0o666 creation permissions.
Dependency selection and lockfiles are untouched by this cleanup.
