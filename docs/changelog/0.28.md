- Adopt the unchanged 46-file Shared Tooling 0.1.7 snapshot at
  `47cd2ccaf0e8b428f06e6db0262df76cfc1581de`, including the checker and its guide.

  undated sections when supplied a canonical previous version. ic-memory retains

## [0.28.0] - 2026-10-06

### Common setup and audit ownership

- Adopt the unchanged 44-file Shared Tooling 0.1.6 snapshot at
  `a37771f1b6b5fc9a88ed6ab3b705bdda35cd8fa3`, including host/IC installers,
  pin catalogs, checksum fixtures and all six audit definitions.
- Provide explicit `install-tools`, `install-host-tools`, `install-ic-tools` and
  their offline check targets. Make/CI select the checkout’s local bin paths.
  Host and IC sets activate independently, retaining previous and failed candidates.
  Setup has no credential, deployment, server-start or shell-profile effects.
- Remove the local tool catalog and both standalone yq installer paths.
  Cargo-sort, Actionlint, ShellCheck and yq versions/digests are unchanged.
  CI explicitly provisions both sets on Linux, macOS Intel and macOS ARM.
  New native consumer qualification remains separate from upstream fixture success.
- Explicitly bootstrap ripgrep on the Linux/macOS test runners before shared
  pin/tool fixtures. The 0.27.3 CI run failed on all three hosts because that
  prerequisite was missing; setup remains separate from offline validation.
- Reduce the current code hygiene definition to a small product overlay.
  Keep authority, storage, decode, runtime and negative-test obligations local.
  Preserve the frozen prior method and historical reports; old risk scores are
  not comparable to the shared finding-based contract. No automatic new audit
  schedule, repairs or broad gates are added.
- Adoption addresses [#11](https://github.com/dragginzgame/ic-memory/issues/11)
  and [#12](https://github.com/dragginzgame/ic-memory/issues/12); matching native
  host evidence is still needed before considering those acceptance requirements complete.

### Host artifact reuse

- Use registry `ic-host-tools 0.1.10` for constant-memory file hashes and strict
  lowercase digest parsing. Remove the local shasum process/output parsing.
  Keep receipt encoding, retained archives, release identity and recovery checks local.
- Select the dependency only for native development targets. Existing selected
  dependency versions and the independent runtime-qualification lock are preserved.
  The host graph gains 22 packages; the Wasm dependency graph gains none.
  No canister code, stable-memory usage or IC instruction change is claimed.

### Compatibility and required setup

- **Breaking developer CLI:** the documented `scripts/dev/install-yq.sh` command
  and `ci-tool-versions.env` selection are removed. Use `make install-tools` for
  the complete set, or `make install-host-tools` before parser/release checks.
  `make tools-check` verifies the complete local set; full validation verifies
  the host parser pair without downloading. Prepare Rust and cargo-sort separately.
- Library APIs, persisted layouts and qualification receipt schemas are unchanged.
  This minor release is selected for the developer setup hard cut, not a data reset.
  Package metadata remains 0.27.3 during preparation.
- See the [adoption evidence](../audits/recurring/shared-tooling-adoption-2026-10-06.md)
  for the existing-report walk, focused commands, failed attempt and host limitations.
