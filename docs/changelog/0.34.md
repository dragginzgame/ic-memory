# 0.34 release notes

## [0.34.0]

### Breaking: one host-wide allocation pool

Replace per-owner numeric ranges and fixed component declarations with permanent
key requests and named owners. The host supplies `MemoryAllocationPool` with
disjoint `MemoryAuthority` namespace grants and explicit unmanaged exclusions.
All owners share eligible application IDs. Governance stays excluded; populated
unmanaged pool IDs fail closed. Known keys keep IDs; omitted, reserved and retired
records never free space. [#44](https://github.com/dragginzgame/ic-memory/issues/44).

Consumers must regenerate macros/callers directly: snapshot construction accepts
requests only, bootstrap requires the explicit pool, and opens accept only a key.
Remove range declarations/DTOs/modes, fixed registrations and `_by_key` aliases.
Doctor reports expose source requests and the tested pool; allocation rows expose
`pool_eligible` instead of per-range ownership. Resolved declarations are private.
Libraries verify/adopt the host's commitment rather than bootstrap independently.

The existing durable format, governance root, geometry and key-to-ID bindings
are retained. Previous owner labels were never stored; current host namespace
grants define owner policy. No compatibility path, reset or format converter is
introduced. The maintainer reports no current deployed users. Product-specific
admission, database recovery and unresolved external effects remain downstream.
See the [symbol retirement inventory](../allocation-pool-removals.md) and
[contract and qualification](../allocation-pool-qualification.md), including
owning Canic, IcyDB, Blob and Jobs adoption links and remaining IC/native evidence.

### Developer and CI tooling

Release preparation updates a unique README dependency version without requiring
the old version's exact spelling. TOML spans preserve spacing, comments and
inline-table options. Missing, ambiguous or unsupported examples remain unchanged
and produce a nonblocking reminder; review documentation during normal maintenance.
The package and lockfile version, validated source/payload, destination and
interruption-recovery checks still govern release acceptance.
[#49](https://github.com/dragginzgame/ic-memory/issues/49).

Adopt reviewed Shared Tooling **0.2.10**, revision
`43a0dc46cdc3c77e70a68e192561642ed50a3e0f`, as one 89-file snapshot. Formatting
wraps Memory's two-workspace sorter/formatter sequence once and prints concise
success; failed logs and exact failing status stay retained, including in CI.
[#48](https://github.com/dragginzgame/ic-memory/issues/48),
[Shared #92](https://github.com/dragginzgame/shared-tooling/issues/92).

Reject unsafe Make execution modes even when explicit `MAKEFLAGS` replacement
hides them. The local parse guard precedes dispatch and preserves normal jobserver
settings and failure propagation. [#47](https://github.com/dragginzgame/ic-memory/issues/47),
[Shared #30](https://github.com/dragginzgame/shared-tooling/issues/30).

Native CI reads back exact uploaded artifact IDs through authenticated REST,
scoped to this repository/run, and treats digest mismatch as failure before the
independent retained-evidence comparison. [Shared #93](https://github.com/dragginzgame/shared-tooling/issues/93).
The existing pinned action identity is unchanged. Hosted acceptance of these
working changes is still required. [Tooling qualification](../release-workflow-qualification.md#0340-shared-tooling-and-make-admission).

The follow-up flow audit removes duplicated resolved rows from the runtime:
source snapshots carry only requests, and the committed capability owns current
placement/schema metadata. Owner projections borrow the bound host pool.
Namespace/physical admission converges at resolution before custom validation;
the governance adapter does not repeat it. Custom validation failures now carry
the policy's error directly, removing `RuntimePolicyError`. This is part of the
same 0.34.0 hard cut. [Audit](../audits/recurring/allocation-pool-flow-2026-10-10.md).
