# 0.37 release notes

## [0.37.0] - 2026-10-14

Retained package copying uses Host 0.17.9's regular-file descriptor admission.
Replacing a hashed source with a FIFO now returns a typed refusal without
waiting for a writer; directory replacement is rejected before copying. Digest
comparison, retained rehash, publication cleanup and earlier release evidence
remain intact. The root native development dependencies require compatible
Host 0.17.9 minimums; the incoming lockfile already selected those versions.
This also selects the published Darwin permission fix, but Linux validation
does not establish native macOS acceptance. Library APIs, stored bytes and the
independent runtime graph are unchanged
([#83 — Prevent retained-package FIFO hangs](https://github.com/dragginzgame/ic-memory/issues/83),
[#62 — Qualify shared tooling and native evidence](https://github.com/dragginzgame/ic-memory/issues/62)).

Adopt committed Shared Tooling 0.12.4
`8b2dbd70a24330fdc6c102a01772f4d3e5b628d7`, with 80 roots and 109 payloads.
The local retention checker delegates its common seven-case exit injection,
status and retained-evidence checks to Shared, retaining its own fixture roster,
actual checker contradiction test and aliased archive round trip. The selected
evidence action uses Shared's canonical tool collector; the release finalizer
requires numbered candidates at the top. Tool pins, library APIs, stored bytes
and the independent runtime graph remain unchanged
([#81 — Adopt canonical fixture-retention probes](https://github.com/dragginzgame/ic-memory/issues/81),
[Shared #174 — Share fixture-retention qualification](https://github.com/dragginzgame/shared-tooling/issues/174)).

Remove the key-only size example, which was byte-for-byte identical to the core
probe, and retire its build and budget entries. Core, admission, diagnostics and
runtime integration keep their distinct qualification; historical measurement
tables remain preserved. This avoids duplicate contributor builds without
claiming a production Wasm reduction
([#80 — Retire the duplicate key-only Wasm probe](https://github.com/dragginzgame/ic-memory/issues/80)).

New requests share one forward scan of the bounded allocation-ID domain instead
of rescanning already assigned IDs. The recovered occupancy map retains every
historical slot, including omitted and retired keys; consuming an ID from the
iterator prevents reuse without updating that map. Canonical request order,
lowest-free placement, exclusions and typed exhaustion remain unchanged
([#79 — Avoid repeated free-slot scans](https://github.com/dragginzgame/ic-memory/issues/79)).

In 21 paired native release measurements, the median time for ten resolutions
of 245 new requests falls from 545 to 222 microseconds. Allocation counts and
peak bytes are unchanged. This measures native declaration resolution; IC
instruction cost is unmeasured. The public API and persisted bytes are unchanged,
so this is compatible patch work.

Detailed allocation reports now contain one `summary: MemoryAllocationSummary`
and the per-ID `memories` rows. Callers must read numeric totals through
`report.summary`; JSON clients must read the nested `summary` object. No flat
aliases are retained. Summary-only measurement still avoids per-ID rows and
string copies, and both paths share the same bounded metadata measurement,
conservation equations and persisted/runtime mismatch checks. Stable-memory
formats and allocation policy are unchanged
([#84 — Compose allocation reports from their summary](https://github.com/dragginzgame/ic-memory/issues/84)).

Ledger publication prepares one bounded encoded payload before reserving Cell
capacity, then lends those exact bytes to the canonical Cell writer. It removes
repeated sizing serialization without adding a persistent encoding cache or
writing the Cell envelope locally. Fresh Cell acquisition still precedes
admission; committed authority is published only after the final write. Encoding
rejects a chunk that would exceed the recovery ceiling before buffering it.
A bounded capacity hint avoids repeated buffer growth without reconstructing
CBOR layout. Across the existing 12 native encoding cases, allocation counts
remain unchanged and no reallocations occur; peak capacity increases by 89–97
bytes. Native timing does not establish IC instruction cost.
Stored bytes, corruption recovery and backing-refusal custody are preserved
([#85 — Prepare bounded ledger bytes once](https://github.com/dragginzgame/ic-memory/issues/85)).

Matched Rust 1.99 size-profile builds with the same selected dependency graph
reduce all four maintained probes by 996–1,729 raw Wasm bytes and 779–1,477
bytes after Binaryen 133 `-Oz`. These are whole-probe measurements, not a fixed
saving per memory. Public report access and serialization change, requiring a
minor release; stored ledger and Cell bytes remain unchanged.

README dependency rendering now delegates to Shared's advisory helper. The
consumer supplies its package and candidate version, retains exact helper input
custody, and passes successful helper reminders into native logs. Missing,
ambiguous and unsupported dependency examples remain unchanged and non-blocking.
Release identity, metadata admission, publication and rollback stay local
([#87 — Adopt the canonical advisory README renderer](https://github.com/dragginzgame/ic-memory/issues/87),
[Shared #178 — Own advisory README dependency rendering](https://github.com/dragginzgame/shared-tooling/issues/178)).
