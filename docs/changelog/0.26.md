# Detailed notes for 0.26

## [0.26.0] - 2026-10-05

- Delegate all three maintainer release targets to the unchanged Shared Tooling
  runner at `f52c0e2476aee094359ed21de91c468540d3969f`. It owns version increments,
  ordering, saved intent, lock handling and exact Git effects. A repeated normal
  target selects unfinished intent before another increment; explicit resume is
  optional. Conflicting identities, payloads and destinations stop recovery.
- Rust adapters consume the selected source, kind, versions, UTC date, remote and
  branch. Save full-gate evidence before metadata mutation, atomically write the
  manifest last, and finish interrupted lock/package preparation using that proof.
  Existing completed checks reuse their exact qualified artifacts. Dependency
  selection changes, corrupted evidence and unrelated source changes are refused.
- Preserve unique full-gate stdout/stderr logs and archive prior successful
  validation receipts before replacement. Prepared/final receipts and qualified
  archives remain available across failure, retry and success. No automatic cleanup,
  package publication or deployment follows a source release.
- **Breaking:** remove `make patch`, `make minor`, `make release-stage`,
  `make release-commit` and `make release-push`, and their Rust phase commands.
  Maintainers use `make release-patch`, `make release-minor`, `make release-major`
  or optional `make release-resume VERSION=X.Y.Z`. The mandatory new receipt shape
  includes saved selection and original validation inputs; old receipts are
  refused without aliases or migration. Finish outstanding earlier releases with
  their original tooling before adoption and preserve their evidence.
- Stage only Cargo/README version edits and the root/candidate minor-line notes;
  both notes receive the same saved UTC date. The selected ignored lockfile is
  qualified but not staged. Publication remains separately authorized and requires
  the final commit/tag/archive evidence.
- The shared installer now owns physical checkout-path resolution. Keep the
  consumer setup target thin and vendor the reviewed installer unchanged.
- Correct consumer hook qualification after adoption is committed. Keep fixture
  loop variables local and explicitly stage each partial-staging case before
  adding its unstaged edit, including formatter configuration. The test no longer
  depends on tooling already differing from HEAD; failures identify their fixture.
- Library APIs, durable stable-memory formats, selected dependencies, toolchains
  and Wasm budgets are unchanged. The release helper is development tooling; no
  runtime instruction, memory or Wasm improvement is claimed. Focused tests use
  command substitutes, not live releases; see the
  [qualification record](../release-workflow-qualification.md) and
  [release guide](../../RELEASING.md).
