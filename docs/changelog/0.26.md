# Detailed notes for 0.26

## [0.26.2] - 2026-10-06

- Apply the existing 256-byte diagnostic text ceiling in allocation-free CBOR
  preflight. Every text field and identifier in the current ledger/record shape
  fits this bound; stable keys retain their stricter 128-byte grammar. Refuse
  oversized advertised text before serde can allocate an owned string, including
  inside arrays, maps and tags.
- Preserve opaque byte-string payloads and their separate byte ceiling. Record
  decoding does not parse the inner ledger; protected recovery checks its current
  envelope and logical text independently. Oversized logical fingerprints still
  return `LedgerCommitError::Codec` and cannot initialize over corrupted storage.
- Add early-rejection, exact-boundary and opaque-payload tests, plus a matched
  native recovery measurement. For an 8 MiB malformed fingerprint, peak requested
  recovery heap falls from 8,388,781 bytes to 200 bytes, excluding the existing
  input buffer. The valid 256-byte control is unchanged. This is failure-path
  allocation evidence, not an IC instruction, Wasm-size, stable-memory or valid
  recovery speedup claim; see the
  [qualification record](../ledger-codec-qualification.md#0262-text-preflight-follow-up).
- Public APIs, accepted durable data, dependency selection and toolchains are
  unchanged. Direct caller-selected serde decoding retains its field validation;
  the earlier preflight belongs to maintained ledger and stable-cell readers.

## [0.26.1] - 2026-10-05

- Serialize logical ledgers through a bounded envelope buffer. Check the next
  slice before appending, clamp geometric capacity reservations to 16 MiB plus
  the 24-byte header, and discard partial output on refusal. Keep one canonical
  serialization pass and the existing `LimitExceeded { resource: "ledger bytes" }`
  error before physical commit mutation.
- Reserve admitted definite collection lengths during recovery instead of
  repeatedly growing their vectors. Keep one spare element for staging in
  non-empty collections below their ceiling. Unhinted decoding still rejects
  excess entries before deserializing them; over-limit hints reject before
  allocation or element decoding.
- Extend native allocation measurements to recovery and commits with large
  fingerprints. The maximum generation-history recovery fixture removes 14
  reallocations per call. Oversized-commit peak requested heap falls from
  25.4 MiB to 16 MiB; a large valid commit falls from 36 MiB to 28 MiB. These
  fixtures contain no allocation records. Timings are variable, including slower
  valid commits; the writer adds checks per serialized slice. No speedup, IC
  instruction saving, Wasm-size or stable-memory saving is claimed. See the
  [codec qualification record](../ledger-codec-qualification.md).
- Cover exact-ceiling and empty writes, refusal without partial append, definite
  collection boundaries, rejection before decoding excess entries, and byte
  equality with the canonical CBOR encoder. Existing corruption, unchanged-store
  refusal, persistence failure and retry tests remain in force.
- Public APIs, durable formats, dependency selections, toolchains and release
  workflow are unchanged. No consumer reset or source change is required.

## [0.26.0] - 2026-10-05

- Delegate all three maintainer release targets to the unchanged Shared Tooling
  runner at `f52c0e2476aee094359ed21de91c468540d3969f`. It owns version increments,
  ordering, saved intent, lock handling and exact Git effects. A repeated normal
  target selects unfinished intent before another increment; explicit resume is
  optional. Conflicting identities, payloads and destinations stop recovery.
- Rust adapters consume the selected source, kind, versions, UTC date, remote and
  branch. Save full-gate evidence before metadata mutation, atomically write the
  manifest last, and finish interrupted lock/package preparation using that proof.
  Existing completed checks reuse their exact qualified artifacts. Dependency
  selection changes, corrupted evidence and unrelated source changes are refused.
- Preserve unique full-gate stdout/stderr logs and archive prior successful
  validation receipts before replacement. Prepared/final receipts and qualified
  archives remain available across failure, retry and success. No automatic cleanup,
  package publication or deployment follows a source release.
- **Breaking:** remove `make patch`, `make minor`, `make release-stage`,
  `make release-commit` and `make release-push`, and their Rust phase commands.
  Maintainers use `make release-patch`, `make release-minor`, `make release-major`
  or optional `make release-resume VERSION=X.Y.Z`. The mandatory new receipt shape
  includes saved selection and original validation inputs; old receipts are
  refused without aliases or migration. Finish outstanding earlier releases with
  their original tooling before adoption and preserve their evidence.
- Stage only Cargo/README version edits and the root/candidate minor-line notes;
  both notes receive the same saved UTC date. The selected ignored lockfile is
  qualified but not staged. Publication remains separately authorized and requires
  the final commit/tag/archive evidence.
- The shared installer now owns physical checkout-path resolution. Keep the
  consumer setup target thin and vendor the reviewed installer unchanged.
- Correct consumer hook qualification after adoption is committed. Keep fixture
  loop variables local and explicitly stage each partial-staging case before
  adding its unstaged edit, including formatter configuration. The test no longer
  depends on tooling already differing from HEAD; failures identify their fixture.
- Library APIs, durable stable-memory formats, selected dependencies, toolchains
  and Wasm budgets are unchanged. The release helper is development tooling; no
  runtime instruction, memory or Wasm improvement is claimed. Focused tests use
  command substitutes, not live releases; see the
  [qualification record](../release-workflow-qualification.md) and
  [release guide](../../RELEASING.md).
