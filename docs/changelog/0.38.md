# 0.38 release notes

## [0.38.1]

The opt-in `test-support` feature exports `test_support::{Counts, Metered}` using
the package's exact stable-structures trait and VectorMemory backend. Clones share
bytes and counters; reset changes only the observation window. Counters clip with
a sticky actual-overflow flag; empty operations remain observable calls. Direct
backend access bypasses observation. These are heap-memory calls rather than IC
instructions, cycles or elapsed-time evidence. No dependencies or stored bytes
change, and ordinary library builds keep the feature disabled.

Internal allocation tests and the allocation example reuse this owner. The
example now requires `--features test-support`; it rejects overflowed observations
before rendering its retained output format. The focused `test-memory-observer`
gate runs with native validation, and the compiler-floor job checks the feature.

## [0.38.0] - 2026-10-14

Native CI delegates formatting and hook fixtures to `validate-toolchain` once
instead of running them again as standalone steps. `test-hooks` supplies the
deliberate CDPATH context for formatter and hook isolation tests. Both maintained
workspaces, release validation and the native host matrix retain their coverage.
Library APIs and Wasm artifacts are unchanged
([#88 — Avoid repeated formatting and hook fixtures](https://github.com/dragginzgame/ic-memory/issues/88)).

Declaration and reservation claims share the new-slot conflict check. Existing
key checks retain their distinct ordering: declarations report retirement before
slot movement, while reservations report slot movement before retirement. The
public errors and persisted contract are unchanged
([#91 — Share claim checks and preserve error precedence](https://github.com/dragginzgame/ic-memory/issues/91)).

Pending bootstrap confirmation retains the successfully committed generation
instead of keeping the entire staged ledger alive during Cell encoding. Ledger
records and keys are released earlier; allocation-open capability still appears
only after stable persistence. Stored formats, generation binding and recovery
rules are unchanged
([#94 — Release staged ledger records](https://github.com/dragginzgame/ic-memory/issues/94)).

Hook fixtures use the selected Shared lifecycle helper for completion, cleanup
and failure retention. Physical fixture anchoring, hook-specific command/output
diagnostics and original error status remain local. Cleanup-refusal injection
and Bash 3.2 qualification cover the delegated path
([#95 — Share hook fixture lifecycle](https://github.com/dragginzgame/ic-memory/issues/95)).

Allocation policies implement only `validate_key` and `validate_slot`. Remove
`validate_reserved_slot` from custom implementations when adopting 0.38.0; no
compatibility callback is retained. Bootstrap and doctor never called that
callback. Hosts still own namespace grants and physical exclusions; explicit
ledger reservation staging still requires caller-owned framework admission.
This is a public trait hard cut, requiring a minor release. Stored ledger and
Cell formats remain unchanged
([#98 — Hard-cut the unused reservation policy callback](https://github.com/dragginzgame/ic-memory/issues/98)).

The bounded ledger encoder and borrowed envelope decoder are private functions.
The owned byte-envelope wrapper exists only in test builds. Encoding remains a
single bounded pass and decoding preserves progressive header error precedence
([#97 — Use private ledger codec functions](https://github.com/dragginzgame/ic-memory/issues/97)).

Doctor reports retain tested policy identity, declaration fingerprint, pool and
established binding as structured fields. Binding mismatch messages now explain
the mismatch without repeating those fields as Debug text. Consumers requiring
full details should render the structured fields; RuntimeBinding classification
and comparisons remain unchanged
([#99 — Remove redundant Debug payload from doctor binding mismatch](https://github.com/dragginzgame/ic-memory/issues/99)).
