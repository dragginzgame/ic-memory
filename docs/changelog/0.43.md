# 0.43 release notes

## [0.43.0]

**Breaking policy API:** implement `type Error`, `validate_key` and `validate_slot`
directly on `RuntimeBootstrapPolicy`, alongside its existing admission and
identity methods. The separate `AllocationPolicy` trait is removed. The common
validation loop skips application callbacks once for the internal ledger key,
checks external keys before their slots, and retains historical ownership checks
for every declaration. Doctor checks share that same loop without replaying
bootstrap admission.

The public resolved `DeclarationSnapshot` and its serialization/decoding contract
are removed. Hosts supply `SealedDeclarationSnapshot` built from `MemoryRequest`
values; the runtime owns checked, canonically ordered numeric assignments.
`AllocationDeclaration` remains a checked public row for metadata and fixture
reservation operations. Durable ledger/Cell decoding retains its bounds and
integrity checks. Internal resolution enforces count, key and slot uniqueness
in one canonical path.

**Breaking admission API:** `BootstrapAdmission::recovered_allocations()` borrows
the validated `AllocationRecord` entries directly. Replace metadata field access
with `stable_key()`, `slot()`, `state()` and `schema()` getters. The duplicate
`RecoveredAllocationMetadata` view is removed. These immutable rows grant no
memory access; current host namespace grants remain the authorization owner.

**Breaking runtime errors:** `RuntimeBootstrapError::Declarations` and
`RuntimeDiagnosticError::Declarations`, including their automatic conversions,
are removed. Runtime declaration failures retain their actual resolution or
historical-admission phase; doctor validation failures remain report checks.
Frameworks building requests or sealing them before runtime bootstrap must keep
those `MemoryDeclarationError` failures in their own composition error instead
of presenting them as a Memory runtime failure.

Fresh bootstrap uses logical generation-zero genesis only when protected recovery
proves snapshot absence. It no longer encodes, hashes or retains an intermediate
physical genesis that would be replaced by the validated generation-one commit.
The existing initial readable Cell acquisition is unchanged, as are failed
admission retry, capacity refusal and persistence-before-publication ordering.
Present snapshots still cross full decoding, checksum, counter and integrity
validation; corruption never becomes genesis. Native allocation measurements now
include fresh runtime bootstrap at representative declaration counts.

Bootstrap and doctor validation share the ledger-owned interpretation of explicit
snapshot absence as logical genesis. The doctor still reports physical emptiness
separately, exports no fabricated committed ledger, and never invokes admission
preparation or writes memory. Present-snapshot failures remain failures in both
paths.

**Breaking diagnostics:** `AllocationBinding::Ledger` is now a unit variant.
Match it directly and use `IC_MEMORY_LEDGER_STABLE_KEY` and
`IC_MEMORY_AUTHORITY_OWNER` when a consumer needs display labels. Its serialized
binding is the string `"Ledger"`, replacing the object carrying those two fixed
strings. Current application bindings still carry their key and owner. Numeric
accounting, eligibility and read-only observation retain their contracts.

`AllocationLedger::stage_validated_generation` is removed. Its required
validation capability was not obtainable through the public API. The runtime
continues to validate, stage an owned ledger, persist and only then publish
committed allocation authority. Stale-generation, ownership, retirement and
bounded-integrity checks remain in the internal staging path.

**Breaking fixture API:** reservation and retirement staging require the existing
`test-support` feature. Import `AllocationRetirement`, `AllocationReservationError`
and `AllocationRetirementError` from `ic_memory::testing`. The staging methods
remain associated with `AllocationLedger`, but their implementation and request
types belong to fixture support. They perform pure logical edits and grant no
runtime persistence authority. Preflight checks, source preservation, counter
overflow and operation-specific error precedence retain their contracts.
Production recovery and bootstrap still understand reserved and retired records,
including their retained-slot and tombstone enforcement.

Release preparation and saved-source recovery reuse IC Build's semantic lockfile
version projection. Memory selects its own package and versions; the independent
check still rejects unrelated dependency changes before accepting rendered output.
Only the unsourced workspace package may change, so a registry package sharing
its name is never rewritten by the semantic verifier.

Native Cargo metadata discovery uses Cargo's canonical command builder and schema,
re-exported by IC Build, with the helper's own Host process capture. No Host process
configuration or error type crosses IC Build's dependency boundary. This keeps the
selected Host 0.21 usable with published IC Build 0.7.0, without a downgrade, another
dependency alias or a local Cargo metadata schema. Discovery remains locked,
offline and bounded to 4 MiB stdout and 64 KiB stderr, with no elapsed-time deadline.
Incomplete output or failed execution is rejected before decoding; original Host
failure evidence is retained. No library API, durable format or canister dependency
changes are involved.
This consumer fix is recorded under
[#9 — Qualify consumers against the current exposed Host boundary](https://github.com/dragginzgame/ic-build/issues/9).

The optional fixture cell releases its temporary runtime after opening the cell.
The opened memory handle retains the shared manager, backing and growth state;
the fixture no longer retains bootstrap declarations, capabilities or policy
metadata. Cross-bucket writes and same-contract reopening continue to use the
ordinary Cell and runtime formats.

These changes do not alter durable manager, Cell or ledger bytes and require no
retained-data reset. Update diagnostic enum matches and serialized report
consumers when adopting this minor release.
