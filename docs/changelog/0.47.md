# 0.47 release notes

## [0.47.0]

### Runtime-owned resolved bindings

Bootstrap returns its persisted generation (`u64`). The runtime owns one resolved
binding vector; `committed_allocations()` borrows its application-only slice and
`committed_generation()` reads the scalar without ledger IO. Publication still
follows successful durable persistence. Repeated bootstrap checks the exact
sealed requests, pool and policy token and retains the same bindings without IO.
Handles retain their independent manager/backing lifetime and exclusive leases.

### Fixture-only numeric inputs

Production callers supply key-only `MemoryRequest` values. `AllocationDeclaration`
is a serializable read view, with numeric constructors and deserialization
available only under `test-support`. Construction errors live under `testing`.
Request grammar errors now use `MemoryDeclarationError::Key` directly. The
resolver and built-in ledger binding retain checked numeric construction inside
the infrastructure boundary. Durable record decoding still rejects sentinel IDs.

### Host-owned diagnostic presentation

Per-ID `MemoryAllocation` rows contain the memory-manager ID, virtual extent and
allocated bucket count. Hosts project current keys and owner labels from the
runtime's borrowed bindings and bound `allocation_pool()`, using
`authority_for_key` for current grants. Fixed ledger labels remain public
constants; unknown ownership stays unknown. Pool membership never proves an ID
is unused. Summary current/ledger/unknown partitions, conservation equations,
corruption checks and the fixed 34,848-byte metadata read budget are unchanged.

This is a source/JSON hard cut. Consumers must update their bootstrap callers,
borrow queries and diagnostic projections together. ICMSNAP1, the logical ledger
encoding, manager and Cell layouts, slot assignments and retained images are
unchanged. No new reset, conversion, dependency selection or tool installation
is part of this change.

### Export ownership

Memory's blanket substrate export was removed in 0.46. Its narrow backing
trait remains available for generic bounds. Storage owns governed collections
and their exact codec interfaces; Metrics Stable owns metric keys, identities,
records and restoration. Admission is enforced by constructors requiring
`RuntimeMemory`, independently of which import path supplies a trait.

### Shared fixture bootstrap and release documentation

`testing::fixture_runtime` accepts explicit backing, owner, namespace, stable keys
and geometry and returns an admitted runtime without initializing collections.
Fixture cells reuse this setup while preserving their existing typed errors.
Unknown keys, duplicate requests, malformed grants, retained bytes and geometry
refusal stay checked through the ordinary runtime. This implements the fixture
sharing proposed in [PR #120](https://github.com/dragginzgame/ic-memory/pull/120).

Release preparation preserves saved README bytes exactly and no longer parses or
rewrites dependency examples. Source/receipt binding, metadata file membership,
manifest/lock/changelog preparation and interruption recovery are unchanged.
The adapter skips byte-identical metadata publication, including the unchanged
README and candidate files already installed before interruption. Tests inject
write refusal for those files: preparation/recovery must succeed without those
writes, while changed-file publication failures retain rollback and evidence.
`Cargo.toml` remains the final source-metadata write when an update is needed.
The canonical exporter narrows the existing Shared 0.15.0 snapshot by one root
and retires its unused renderer; policy, tools and selected revision are unchanged.
This addresses [#119](https://github.com/dragginzgame/ic-memory/issues/119).

### Qualification

Focused library/API/compile-fail tests, strict Clippy with and without
`test-support`, Rust 1.91 all-target compilation, formatting and Rustdoc pass.
The library run has 181 active tests; six measurement cases remain opt-in.
All five locked/offline raw Wasm probes shrink against released 0.46.0:

| Probe | Before bytes | After bytes | Saved bytes |
| --- | ---: | ---: | ---: |
| Core | 158,070 | 157,850 | 220 |
| Diagnostics | 181,445 | 179,478 | 1,967 |
| Admission | 162,029 | 161,755 | 274 |
| Runtime integration | 162,099 | 161,925 | 174 |
| Installed IO artifact | 171,546 | 171,141 | 405 |

Probe artifacts measure these fixture exports, not application Wasm or IC cost.
Canic and IcyDB host-projection patches are prepared with passing extracted
projection/Candid tests against the new Memory API. Full consumer adoption and
installed qualification are separate: Canic main still selects Memory 0.44,
and the prepared Testkit 0.25.4 CLI fails local admission. No dependency, tool
setup, package version or release effects ran. Evidence and prepared patches
are retained under `target/qualification/cleanup0470/`. Consumer integration is
tracked in [Canic #573](https://github.com/dragginzgame/canic/issues/573) and
[IcyDB #355](https://github.com/dragginzgame/icydb/issues/355).

The fixture-runtime addition passes all ten fixture tests on Rust 1.99 and 1.91.
README retirement passes all 56 release-adapter tests and the separate substituted
Make dispatch checks. Snapshot verification confirms 112 payloads at the unchanged
revision. All five current raw Wasm artifacts are byte-for-byte identical to the
preceding 0.47 probes. No installed check or hosted result is claimed for this
uncommitted combined source.
