# Detailed notes for 0.27

## [0.27.1] - 2026-10-06

### Selected release commit recovery

- Adopt the 23-file Shared Tooling snapshot at
  `cb86188c5956866564de4fb6ec6be67b27981ab9` (0.1.4), including the maintenance
  rule. Export committed bytes through a clean temporary local clone; preserve
  the sibling's uncommitted changes. Keep the canonical runner and hooks unchanged.
- Bind late Rust adapters to `RELEASE_COMMIT`, separately from `RELEASE_SOURCE`
  and current HEAD. Read the older commit's version, sole parent, release subject
  and prepared metadata; verify its annotated tag and retained package evidence.
  Newer committed callback fixes can remain in place. Recovery of an older,
  already-qualified release does not require Cargo's replaceable working archive
  to contain that older package.
- Require HEAD to remain the selected release commit when creating final package
  evidence. Advancing to a newer descendant during packaging refuses qualification
  without replacing the prepared receipt/archive or creating a final receipt.
  Reusing already-qualified older releases continues to work.
- Normal commands reconcile the saved release before computing a new candidate.
  An unchanged same-kind retry finishes only the saved release; a newer descendant
  or different increment runs fresh preflight/full validation for the next source.
  Explicit resume selects only the original release. The shared runner owns exact
  identities, atomic push, lost-reply reconciliation and conflict refusal.
- Check the entire index independently during preflight. Accept only exact
  original/prepared metadata on the declared surfaces; restoring working files
  cannot hide unrelated or arbitrary staging. Recheck at commit admission,
  rejecting file-mode changes too. Add a real Git index fixture without
  commits or tags, alongside the separate Rust, Make and runner effect substitutes.
- Preserve the receipt schema and saved lockfile/compiler/configuration bindings.
  Missing final evidence for an older commit still stops: never package newer
  source as the old release. Library APIs, durable bytes, dependencies, toolchains
  and manifest version are unchanged. No runtime footprint reduction is claimed.
  Implements the current consumer adoption scope of
  [#10](https://github.com/dragginzgame/ic-memory/issues/10) and the correction from
  [Shared Tooling #5](https://github.com/dragginzgame/shared-tooling/issues/5).
  See [qualification](../release-workflow-qualification.md#0271-selected-commit-recovery)
  and [maintainer recovery instructions](../../RELEASING.md).

## [0.27.0] - 2026-10-06

### Current ownership ledger — breaking

- Retain only permanent key/ID bindings, current lifecycle state and latest schema
  metadata. Remove generation and schema audit trails, first/last observation
  counters, retirement generation, commit timestamps and runtime fingerprints.
  Repeated cold bootstraps still advance a checked commit counter; they append
  no historical event. Omitted and retired records continue to prevent ID reuse.
- Replace the history wrapper with `AllocationLedger::records()` and current
  `AllocationRecord::schema()`. Use unit `AllocationState::Retired`; remove
  timestamp arguments from bootstrap/staging calls and runtime-fingerprint APIs
  from declaration and allocation capabilities. `DeclarationSnapshot` stores
  declarations only. `checked_reservation_count` returns `Result<(), _>`.
  Diagnostic exports remove `generations`; records expose current schema metadata.
  Remove `MAX_LEDGER_GENERATIONS` and the obsolete history-integrity error variants.
  Sealed-declaration fingerprint values change with the current snapshot shape;
  update diagnostic expectations. These remain transient runtime bindings.
- Collapse the structural/committed-history validators into the one current
  integrity contract. Keep recovery, stale-proof checks, next-counter checks,
  claim conflicts, policy ordering and persistence-before-publication. The two
  physical commit slots and corruption refusal remain. Counter overflow returns
  a typed staging error without mutating the store.
- Bound logical CBOR to 64 KiB and the enclosing record to 128 KiB + 4 KiB.
  Records remain bounded at 255, including governance. Latest-schema churn and
  repeated upgrades no longer increase record count or recovery work; CBOR
  counter width can grow by at most eight bytes. Physical allocation remains
  page/bucket rounded. No IC instruction saving is yet measured.
- **Durable hard cut:** the current envelope uses `ICMEMLED` / `ICMS` / version 1.
  Previous logical layouts are unsupported, with no fallback or automatic reset.
  Regenerate external DTO fixtures and update callers. Retained installations
  need an explicit, application-owned data disposition before deployment; never
  erase ID 0 to bypass recovery. See [the current contract](../current-ledger.md)
  and [focused qualification](../current-ledger-qualification.md).

### Manager diagnostics buffer

- Validate the complete manager bucket table using a fixed 32 KiB local buffer,
  including during reopen. Borrow the buffer when scanning it, preserving the
  existing two reads and 34,848-byte metadata budget without another table copy.
- Matched native measurements cover empty and populated managers before and
  after bootstrap. Numeric summaries remove one 32 KiB heap allocation per call;
  detailed reports remove one allocation but retain the same peak heap because
  their returned rows are larger. The buffer moves to the stack: the measured
  Wasm validator frame grows from 4,656 to 37,408 bytes. The existing runtime
  integration probe's standard-release raw Wasm is 587 bytes smaller; full size
  budgets were not rerun. No total-memory or IC instruction saving is established.
  See the
  [qualification record](../allocation-diagnostics-qualification.md).
- Extend corruption coverage to the last unused bucket-table entry. Existing
  accounting, read-only diagnostics, growth refusal and same-release reopen
  checks remain in place. This buffer change has no API or format impact. The
  complete pending release also contains the breaking ledger change above. Dependencies and toolchains
  remain unchanged.
