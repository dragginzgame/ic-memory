# 0.40 release notes

## [0.40.0]

**Breaking build requirement:** the declared Rust floor is now 1.91.0, explicitly
approved for IC Build 0.4.0. The release helper uses Build's locked, offline,
no-dependency Cargo metadata observer and canonical schema. Memory retains
absolute target-path admission, Wasm budgets, receipt/recovery checks and release
sequencing. Metadata capture is bounded to 4 MiB stdout and 64 KiB stderr, without
an elapsed-time deadline. IC Build is a native-only development dependency;
the normal canister graph excludes it
([#113 — Adopt Build metadata and Rust 1.91](https://github.com/dragginzgame/ic-memory/issues/113)).

Historical admission carries resolved declarations directly into bootstrap,
retaining the checked recovered slot and schema instead of reconstructing an
unresolved request. Canonical snapshot construction checks adjacent keys after
its one sort and shares slot/key refusal ordering with general validation.
Poisoned selections, final policy checks, public snapshot construction/decoding,
physical persistence and current stored bytes retain their existing contracts
([#112 — Carry resolved declarations](https://github.com/dragginzgame/ic-memory/issues/112)).

Matched native declaration resolution saves one allocation per call and 3,936
bytes of peak requested heap at 245 requests. Raw Wasm probes shrink 403–599 bytes;
Binaryen 133 `-Oz` probes shrink 239–555 bytes. Both sides use the incoming
Host 0.18.5 lock and Rust 1.99.0 size profile. Adopting the native Build dependency
leaves all four resulting Wasm artifacts byte-identical. These are separate probe
results, not total canister savings or IC instruction measurements.

Bootstrap and doctor validation reuse one stack-only recovered-slot bitmap for
custody and request resolution. Every retained lifecycle state still owns its
physical ID; unmanaged allocations, exclusions and deterministic assignment keep
their existing refusal/order semantics
([#108 — Reuse recovered-slot membership](https://github.com/dragginzgame/ic-memory/issues/108)).

Doctor reports consume the recovered ledger after validation instead of copying
its keys into a second record set. Bounded numeric scratch preserves memory-size
observations from before custom policy callbacks. The ordinary owned diagnostic
export, recovery errors, DTOs and current bytes remain unchanged
([#109 — Consume recovered doctor records](https://github.com/dragginzgame/ic-memory/issues/109)).

The earlier doctor-only comparison used the Host 0.18.4 graph. At 245 stores
with 128-byte keys, each report saves 246 allocations; peak requested heap falls
from 133,649 to 116,971 bytes.
Preserving pre-policy sizes uses 2,040 bytes of bounded stack scratch. The
diagnostics probe grows 177 raw / 165 `-Oz` bytes; core shrinks 22 / 30 and
admission shrinks 20 / 74, while runtime integration grows 2 / 45. These are
separate probe results, not a whole-canister size or IC instruction claim.

The optional `test-support` feature exposes `testing::FixtureCell` for explicit
fixture byte cells. Callers choose the backing memory, owner, namespace, stable
key and manager configuration; the helper retains the ordinary allocation runtime
and Cell. Hosts retain codecs, byte/work limits, lifecycle handlers and restored
journal validation. No global bootstrap, dependency or alternate wire format is
introduced. This uses the current 0.39 snapshot contract; it does not admit
pre-cut images
([#104 — Share fixture byte-cell construction](https://github.com/dragginzgame/ic-memory/issues/104)).

`make test-fixture-cell` exercises the feature's reopen/configuration-refusal
tests, strict lint and Wasm compilation. Native validation includes that target;
MSRV CI also enables the feature on every selected host. Ordinary library builds
leave it disabled.
