# 0.36 release notes

## [0.36.4] - 2026-10-13

Reduce duplicated sorting code in bootstrap and uniqueness validation with one
in-place heap sorter. Already ascending or descending inputs take linear work;
arbitrary inputs retain O(n log n) worst-case work and constant auxiliary space.
Canonical ordering, fingerprints, collision/error precedence and allocation
placement remain unchanged. Namespace grants validate their borrowed prefix
against the same complete-key bound and segment grammar, without constructing
and discarding temporary owned keys
([#78](https://github.com/dragginzgame/ic-memory/issues/78)).

Matched Rust 1.99.0 size-profile probes shrink by 4,377–4,565 raw Wasm bytes;
the [measurement table](../measurements/wasm-bounded-sort.csv) records the raw
and Binaryen 133 `-Oz` results. These are whole-probe savings in shared runtime
code, not a fixed saving per allocated memory. Shuffled maximum-sized records
sort more slowly in the native microbenchmark; native timing does not establish
IC instruction cost. Public APIs, storage bytes, dependencies and IO paths are
unchanged.

The independent library-only bootstrap/read/write probe with one application
memory shrinks by 9,987 raw bytes and 9,109 optimized bytes. Its baseline and
candidate use identical dependency features; the maintained example probes
use their own unchanged development-dependency feature unification. The first
stable map still adds about 16.7 KiB for its collection operations; sharing
runtime sorting does not remove that upstream collection implementation.

Adopt committed Shared Tooling 0.11.4
`031d214ed044705b989d43e2379f30e6a3d44749`, selecting 78 roots and 105 payloads.
CI invokes `install-ci-tool.sh actionlint` and `install-ci-tool.sh shellcheck`
with the same version, checksum and destination arguments. Canonical refresh
retires the unchanged forwarding scripts; no aliases or tool upgrades are added
([#74](https://github.com/dragginzgame/ic-memory/issues/74),
[Shared #161](https://github.com/dragginzgame/shared-tooling/issues/161)).

Native evidence readback downloads the exact uploaded artifact directly, binding
its ID and digest to the current repository/run and explicit read token. Reported
HTTP 404 responses get bounded retries at both metadata and ZIP download; other
transport, authentication, identity, checksum and member failures remain terminal.
Each attempt stays retained. The helper verifies the ZIP digest and admits only
the expected archive member before Memory checks its product payload against the
retained oracle. The consumer fixture checks Memory's single-upload bindings;
Shared's two-upload workflow fixture remains at its producer
([#74](https://github.com/dragginzgame/ic-memory/issues/74),
[Shared #158](https://github.com/dragginzgame/shared-tooling/issues/158)).

The snapshot also adopts strict CI selector admission and shared-store path
checks. The 0.11.1 runner uses the common annotated-tag checker, and selected
portable fixtures use its canonical completion/retention helper. Compiler/MSRV,
common tool pins, Testkit/PocketIC,
public APIs, stored bytes and Wasm dependency selections remain unchanged.
This is compatible contributor-tooling work for a patch release.

Memory's native adapter delegates annotation and exact commit admission to the
same shared tag checker, capturing the tag object before and after that check.
Tag replacement or disappearance stops publication; later receipt and remote
checks retain their existing boundaries
([#75](https://github.com/dragginzgame/ic-memory/issues/75)).

The two ordinary local fixture handlers use Shared's corrected lifecycle helper.
Created directories resolve physically before trap registration, including
relative/symlink TMPDIR, and cleanup failures remain failures. Failed diagnostics
do not replace the original status. Actual caller probes retain evidence bytes
and reject premature success on both top-level and function failures. Hook
diagnostics and explicitly retained round-trip fixtures keep their local policy
([#77](https://github.com/dragginzgame/ic-memory/issues/77),
[Shared #166](https://github.com/dragginzgame/shared-tooling/issues/166)).

The maintainer-selected native Host artifacts/fs/process 0.17.6 graph is qualified
without changing its selection. Default features stay disabled; it adds
no canister dependencies and does not change the independent runtime graph.

Saved-source manifest rendering uses Shared's pure literal workspace-version
helper. Memory retains parsed source admission and independently verifies that
the candidate changes only the workspace package version, including rejection of
valid-looking helper output that changes other metadata. The five-file release
transaction, exact byte comparisons, partial-preparation recovery and dependency
guard remain local. No broad Cargo metadata adapter replaces these obligations
([#76](https://github.com/dragginzgame/ic-memory/issues/76),
[Shared #159](https://github.com/dragginzgame/shared-tooling/issues/159)).

## [0.36.3] - 2026-10-13

Adopt Shared Tooling 0.10.2 with 76 entrypoints and 103 payloads, including its
canonical local-package lock rewriter.
Common host/Cargo and IC catalogs derive from their installers; all versions and
platform digests remain unchanged. Setup, formatting, native reuse and compact
failure evidence select the reviewed snapshot without consumer-local discovery
or host-to-Rust pin inheritance. Memory needs no exception catalogs
([#71](https://github.com/dragginzgame/ic-memory/issues/71),
[Shared #153](https://github.com/dragginzgame/shared-tooling/issues/153)).
Refresh prepared tools explicitly with `make install-tools`, then run offline
`make tools-check`. Compiler/MSRV, application dependencies, Testkit/PocketIC
and library contracts remain unchanged; this contributor tooling change is
compatible with the patch release.

Cargo CI cache keys ignore comments, record order and unrelated pins in literal
catalogs while retaining Cargo selections and build identities. Ambiguous or
executable catalogs keep conservative byte-based keys and are never executed
during inspection ([Shared #154](https://github.com/dragginzgame/shared-tooling/issues/154)).
Fleet dashboard changes remain Shared-owned and are not imported.

The selected Host artifacts/fs 0.17.2 helpers remain native-only with default
features disabled. Their released implementation is unchanged from 0.17.1;
the patch's process/tools fixture and example cleanup adds no canister code.

The compile-fail fixture now attempts to replace a committed capability's
persisted generation through its private fields. It verifies that consumers
cannot fabricate persistence authority from an existing capability without
relying on a removed constructor name or an unrelated spelling suggestion
([#72](https://github.com/dragginzgame/ic-memory/issues/72)). Runtime publication,
public APIs, durable bytes and Wasm build selections are unchanged.

Bootstrap fixtures use the existing ledger staging and production validation
paths instead of maintaining separate test-only initialization, reservation and
retirement orchestration. Ledger and runtime tests retain the generation,
corruption, reservation and retirement behavior checks. Runtime-owned stable
persistence and capability publication remain unchanged
([#73](https://github.com/dragginzgame/ic-memory/issues/73)).

Native release helpers use `ic-host-process` 0.17.3 with default features
disabled. Captured commands preserve complete output, typed failures and the
original status without introducing a finite deadline; foreground commands
retain inherited stdio. Changelog and lock transforms share retained file inputs,
checked before and after execution, avoiding sequential stdin writing and pipe
draining. Shared Tooling owns the lock rewrite algorithm; Memory independently
checks that only its local package version changed. Partial output never installs
release metadata. This dependency adds no canister code and does not change the
independent runtime qualification graph
([#73](https://github.com/dragginzgame/ic-memory/issues/73)).

## [0.36.2] - 2026-10-13

Stable-key validation matches whitespace, forbidden separators and the final
`.v` suffix as bytes after rejecting non-ASCII input. The checks retain all six
ASCII whitespace characters, including vertical tab, and preserve earlier
ASCII/lowercase failures, last-suffix selection and rejected-key context.
No grammar, public API or durable encoding changes are required
([#68](https://github.com/dragginzgame/ic-memory/issues/68)).

Integration, safety, operations and audit guidance now describe explicit component
requests and runtime-owned persistence. Remove examples of retired registration
hooks and manual persistence confirmation; doctor helpers take the supplied
snapshot. Historical qualification reports remain unchanged
([#70](https://github.com/dragginzgame/ic-memory/issues/70)).

Bounded declaration and ledger uniqueness checks share heap-sorted borrowed
keys. Original positions preserve each boundary's key/slot error precedence;
count admission remains before allocation, and both validation boundaries remain.
The selected size reduction trades higher native validation cost for some
maximum-size input orders; IC instruction cost is not established
([#69](https://github.com/dragginzgame/ic-memory/issues/69)).

CBOR reads use a borrowed slice while retaining syntax bounds, exact consumption
and typed failures. Stable-key segments also use byte iteration after ASCII
admission. Impossible internal serializer failures still panic without pulling
in error formatting; recoverable size failures and decode diagnostics remain
unchanged. No public API, persisted format or dependency selection changes.

The maintainer-selected Host artifacts/fs 0.17.0 graph is qualified separately.
Both dependencies remain native-only with default features disabled; Host's
Wasm/Candid inspection feature cut concerns `ic-host-tools`, which Memory does
not use. Compiler/tool pins and the independent runtime graph remain unchanged.

## [0.36.1] - 2026-10-13

### Request resolution

After owner admission, resolved declarations need only the key and schema.
Borrowed component requests now copy those fields directly; historical admission
selections transfer their owned fields. The already-checked owner string is no
longer cloned and immediately discarded. Input snapshots, error context, stable
key placement, retained IDs and durable encoding are unchanged.

The optional native allocation measurements now include 1-, 32- and 245-request
resolution cases with bounded owner metadata. They report allocator operations
without adding a deployment gate or an instruction-performance claim.

### Contributor tooling

Adopt Shared Tooling 0.9.13 from committed source
`35cad65677ff989b5fb24a88d947fda37d2366e8`, retaining the same 77 roots and
102 payload files. Store/checkout locks preserve filesystem errors without
removing existing locks, and Cargo source acquisition preserves its original
failure status before build or activation
([Shared #145](https://github.com/dragginzgame/shared-tooling/issues/145),
[#146](https://github.com/dragginzgame/shared-tooling/issues/146)). The changed
build-helper identity requires `make install-rust-tools` followed by
`make rust-tools-check`; earlier generations and evidence remain retained.

CI inspection requires an observable current branch or an explicit branch,
commit or run, avoiding an unintended repository-wide selection
([Shared #148](https://github.com/dragginzgame/shared-tooling/issues/148)).
Authorized development and validation may separately fetch missing sources for
the existing lockfile without another approval; explicit offline settings remain
authoritative, and ordinary gates still run offline
([Shared #147](https://github.com/dragginzgame/shared-tooling/issues/147)).

The selected Host artifacts/fs 0.16.0 dependencies remain native-only with
default features disabled. Host's extraction-feature cut concerns
`ic-host-tools`, which Memory does not use. The library API, Wasm dependency
graph, compiler/tool pins and independent runtime graph remain unchanged.

## [0.36.0] - 2026-10-13

### Shared tooling and prepared tools

The 77-root/102-payload roster selects committed Shared Tooling
**0.9.10**, `7e55adecf6f0b196c050f104b37f8c69b6bf434e`.
User Cargo `net.offline` configuration must retain its TOML boolean type;
strings, numbers and other malformed values reject before tool setup/admission.
Explicit nonempty `CARGO_NET_OFFLINE` overrides still take precedence. Empty
configuration and a missing setting retain the existing default, and Cargo's
`config` file takes precedence over `config.toml`
([Shared #140](https://github.com/dragginzgame/shared-tooling/issues/140)).

The changed build-helper digest requires explicit prepared Cargo-tool refresh
with `make install-rust-tools`; offline checks never repair selection. Existing
builds remain retained. Pinned tool versions and compiler are unchanged.

The common PR helper admits complete JSON repository/commit/PR identities before
shell extraction or state writes, rejecting newline-suffixed identities and
malformed response shapes. Repository observations remain separately retained
across retries ([Shared #139](https://github.com/dragginzgame/shared-tooling/issues/139)).
Memory retains direct delivery and does not enable PR release execution.

The selected Rust-tool fixture now derives the producer's read-only CI cache-key
helper as a companion. Shared owns the native cache transport and portable-suite
timings; Memory retains its existing CI setup/admission workflow.

The maintainer's selected root lock uses Host artifacts/fs **0.15.1** for release
helpers. Removing Memory's constructor dependency prunes only `ctor` and its
macro helper from the root graph; the independent runtime lock is byte-identical.
Other selected versions, sources and features remain unchanged. The tooling/Host adoption itself is compatible;
the explicit declaration contract below requires this minor release.
[#62](https://github.com/dragginzgame/ic-memory/issues/62) retains delivery and
matching native/hosted acceptance.
The canonical 0.9.10 Rust fixture qualifies from a neutral working directory
and borrows existing immutable history while refusing commit/tag/push commands
([Shared #143](https://github.com/dragginzgame/shared-tooling/issues/143),
[#144](https://github.com/dragginzgame/shared-tooling/issues/144)).

### Breaking: explicit declarations and runtime-owned persistence

Components provide complete `Vec<MemoryRequest>` lists. The host combines them
and calls `SealedDeclarationSnapshot::new(requests)`, which takes ownership,
rejects duplicate keys and canonicalizes the bounded snapshot. Default bootstrap
and doctor helpers now take that snapshot explicitly. Request failures use
`MemoryDeclarationError`; runtime errors identify them as `Declarations`.

Constructor macros, global registration, deferred eager hooks and their lifecycle
are removed. Store opening uses `open_default_memory_manager_memory(key)` after
host bootstrap. Generators must produce their component's complete requests,
including stores whose lazy initializers have not run. Libraries verify their
own requirements against the existing host; adoption does not bootstrap again.
See the [composition example](../../crates/ic-memory/examples/composed_host.rs).

Manual bootstrap, pre-commit authority and raw physical commit writers are
internal to Memory. `MemoryRuntime` persists before publishing committed
allocations; callers cannot mint authority by confirming their own write.
Typed errors, ledger diagnostics and immutable committed capabilities remain.

The durable format, stable keys, retained physical IDs, bounded admission and
recovery rules are unchanged. This is a source/generator update, requiring no
stable-memory reset or compatibility decoder. Canic and IcyDB must adopt the
explicit component/host boundary together before applications select 0.36.0
([Canic #527](https://github.com/dragginzgame/canic/issues/527),
[IcyDB #355](https://github.com/dragginzgame/icydb/issues/355)).
Retained native allocation measurements now live inside the library; their
populated backing fixture declares its actual unmanaged physical exclusions.
