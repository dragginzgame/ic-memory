# Detailed notes for 0.30

## [0.30.0] - 2026-10-07

### Rust workspace locations

- **Breaking checkout layout:** the library package is now
  `crates/ic-memory/`. Update checkout path dependencies to that directory and
  package-specific manifest references to `crates/ic-memory/Cargo.toml`.
  Its source, examples, tests, wire fixtures and canonical package guide move
  together. The repository README provides navigation to that guide.
- The repository-root manifest is virtual. Its package metadata, dependency
  catalog, lints, profiles and selected lockfile remain authoritative. The sole
  default member inherits them; normal root Make/Cargo commands retain their
  existing targets and publication selection.
- The approved independent workspace remains at
  `testing/runtime-qualification/`, with the unpublished package under its own
  `crates/ic-memory-runtime-qualification/`. Its root owns its metadata/catalog
  and separate lockfile. PocketIC remains outside the library's normal graph.
- Preserve package names, selected versions/features, edition, resolver, MSRV,
  Rust pin, public APIs and durable wire bytes. The pending minor reflects the
  checkout path change, not a runtime or dependency upgrade. Package manifests
  retain their existing versions until maintainer release preparation.
- Release adapters read and replace the root workspace version, require the
  named library package to inherit it, and update the package guide's dependency
  example. Metadata ordering, receipts, saved intent and recovery remain local.
  The launcher projects the virtual workspace and member manifest into its
  retained bootstrap when the selected lock already has the candidate version.
- Package inventories retain source, examples, tests, fixtures, the full guide
  and an unchanged copy of the repository's MIT license. CI scripts, governance
  and operational evidence remain repository-owned outside the crate archive.
- Adopt the committed Shared Tooling 0.1.13 governance snapshot, including its
  workspace-layout rule. Newer uncommitted sibling tooling is not exported.
  Hook fixtures use both virtual-root layouts and cover partial staging of root
  and member manifests. Release fixtures keep process/Git effects substituted.
