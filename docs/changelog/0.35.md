# 0.35 release notes

## [0.35.3] - 2026-10-10

### Binaryen 133 and installed runtime qualification

Refresh the same 91-file selection from committed Shared Tooling **0.3.4**,
`169d77b8440568c5200eede971625126181f7bb2`. Prepare the new IC bundle explicitly
with `make install-ic-tools`; ordinary offline checks never replace it. Previous
bundles and failed candidates remain retained. Memory does not use Shared's
validation-target runner, so its 0.3.3 repair requires no additional adoption.

Existing `make test-runtime` now checks the original fixture and Binaryen's
`-O3`, `-Os` and `-Oz` outputs with the unchanged independent runner. Optimization
admits only the required `memory.copy`/`memory.fill` feature in addition to the
module's declared features. Each variant exercises startup, IO rejection and
upgrade rollback through a separately managed Testkit server. Native runtime CI
prepares the selected IC tools and runs the same checks on all three supported
hosts. Input hashes, generated Wasm and optimizer/server/runtime logs remain
available after failure. Library gates gain no PocketIC dependency; normal Wasm
builds and their budgets remain unoptimized.
[#53](https://github.com/dragginzgame/ic-memory/issues/53),
[Shared #102](https://github.com/dragginzgame/shared-tooling/issues/102).

Preserve the incoming Host 0.12.3 lockfile selection. Its artifact/filesystem
library sources are unchanged from 0.12.2; the update affects upstream tooling.
This is a compatible tooling patch, with no canister API, durable format,
compiler, PocketIC client/server or independent dependency graph change.

See [installed qualification](../runtime-io-qualification.md#binaryen-133-current-fixture-qualification).

## [0.35.2] - 2026-10-10

### Parallel Cargo and trustworthy fixture completion

Adopt committed Shared Tooling **0.3.2**,
`c16444bf006f17c5bb4dda5ad070a0f345da9623`, through the canonical exporter.
The 91-file selection adds the linked advisory README freshness task. It adds
no schedule, automatic prose rewrite or release gate.

The shared tool include admits Make execution before dispatch and preserves
Cargo jobserver descriptors through Rust setup/check and LOC commands. Memory's
own two-workspace formatting, Cargo, compiled release-helper and Testkit-helper
recipes now preserve those descriptors too. Unsafe Make modes still refuse
before substituted effects. [Shared #99](https://github.com/dragginzgame/shared-tooling/issues/99).

Selected shared tests require explicit completion before success/cleanup.
Memory's release-adapter, hook and failure-evidence fixtures now do the same.
Early zero-status exits and Bash 3.2 unset-variable failures return failure and
preserve their scratch evidence; completed failures retain their original
status. Fault injection exercises the actual handlers without executing fixture
bodies, and parallel Make probes the actual consumer recipes with substituted
Cargo, formatting and release effects.
[Shared #103](https://github.com/dragginzgame/shared-tooling/issues/103).
[#52](https://github.com/dragginzgame/ic-memory/issues/52) tracks the consumer
repair; see [qualification](../release-workflow-qualification.md#0352-shared-032-parallel-cargo-and-fixture-completion).

This is a compatible tooling patch. Host 0.12.2 is already selected by the
delivered Memory 0.35.1 lockfile; its filesystem/artifact library sources are
unchanged. Both dependency graphs, compiler/runtime selections, canister API and
durable format remain unchanged.

## [0.35.1] - 2026-10-10

### Setup prerequisite checks and diagnostics

Refresh the same 90-file selection from committed Shared Tooling **0.3.1**,
`fa452afaa5012866eb1c20820dfa8038c106e7ec`. Common `install-tools` checks
platform/catalog and checkout-selected Rust/Cargo before host, IC, Cargo or
product installation. These silent read-only preflight calls do not install
toolchains, download tools or replace retained receipts. Narrow setup commands
and ordinary offline `tools-check` retain their existing roles.

Host-tool checks report the failing executable, expected version, selected path,
reason, available probe output and repair command. Byte authentication still
precedes executable probes, and earlier bundles and failure evidence remain.
The upstream fixtures qualify prerequisite refusal and aggregate ordering,
including parallel Make and product extensions. No new consumer gate or tool
selection is introduced. [#51](https://github.com/dragginzgame/ic-memory/issues/51),
[Shared #101](https://github.com/dragginzgame/shared-tooling/issues/101).

This is a compatible tooling patch; the canister API, durable format and both
dependency graphs are unchanged.

## [0.35.0] - 2026-10-10

### Breaking tooling setup: complete common tools

Adopt committed Shared Tooling **0.3.0** at
`88a73139a0f083344c41a6f6f4b5c3a8aca7dc1d` through the canonical exporter.
The common aggregate always installs/checks jq, yq, ripgrep with PCRE2, cloc,
five IC tools, cargo-sort, cargo-sort-derives and candid-extractor in that order.
Direct host-installer `--with-ripgrep` and `--with-cloc` options are removed;
call the existing common targets instead. Prepare the declared Rust toolchain
first, run `make install-tools`, then run offline `make tools-check`.
[#50](https://github.com/dragginzgame/ic-memory/issues/50),
[Shared #98](https://github.com/dragginzgame/shared-tooling/issues/98).

Memory uses the same canonical aggregate in CI and coherent release preflight.
Standalone validation checks complete common admission before dependent builds,
including under parallel Make. Interrupted metadata recovery checks the retained
selection without replaying setup. CI selects local Cargo tools, removing its
duplicate global formatter installation; exact two-workspace formatting remains.
PocketIC/Testkit preparation stays a separate explicit command and is not added
to library gates. The canister API, durable format, compiler and dependency
selections are unchanged. This setup/installer contract cut requires a minor
release and supersedes the unreleased compatible 0.34.2 candidate.

### CI inspection

The preceding 0.2.14 CI-helper repair is carried forward. Failed, unfinished or
unknown runs with missing failed-step logs report unavailable evidence;
completed successful, neutral or skipped runs may legitimately have none.
Retrieval failures preserve status and retain partial observations.
[Shared #97](https://github.com/dragginzgame/shared-tooling/issues/97).
The upstream fixture remains part of Memory's tooling gate. Earlier focused
[evidence](../release-workflow-qualification.md#0342-shared-0214-ci-log-evidence)
retains its original inputs; full adoption evidence belongs to the current batch.

See [qualification](../release-workflow-qualification.md#0350-shared-030-complete-common-tools).
