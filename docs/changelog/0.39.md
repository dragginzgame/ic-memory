# 0.39 release notes

## [0.39.1]

The optional `test-support` feature exposes `testing::FixtureCell` for explicit
fixture byte cells. Callers choose the backing memory, owner, namespace, stable
key and manager configuration; the helper retains the ordinary allocation runtime
and Cell. Hosts retain codecs, byte/work limits, lifecycle handlers and restored
journal validation. No global bootstrap, dependency or alternate wire format is
introduced. This uses the current 0.39 snapshot contract; it does not admit
pre-cut images
([#104 — Share fixture byte-cell construction](https://github.com/dragginzgame/ic-memory/issues/104)).

`make test-fixture-cell` exercises the feature's reopen/configuration-refusal
tests, strict lint and Wasm compilation. Native validation includes that target;
MSRV CI also enables the feature on every selected host. Ordinary library builds
leave it disabled.

## [0.39.0] - 2026-10-15

Native runtime CI restores the canonical Cargo source/tool store and Testkit
server setup through an optional cache. The reviewed compiler/native-image/tool
key and Memory's Make selection separate incompatible inputs. Cache transport
has a three-minute bound; a miss or transport failure still runs normal setup.
Restored bytes never replace installer admission or offline CLI/server checks.
Only verified main-branch setup publishes caches. All native hosts, selected
versions and original/optimized IO and upgrade checks remain required. Warm CI
reuse is not yet measured on macOS
([#62 — Qualify native tooling and evidence](https://github.com/dragginzgame/ic-memory/issues/62)).

Logical ledger and Cell encoders share one bounded writer. The ledger retains its
header and limit error; Cell publication retains the exact rejected size and
borrowed Storable bytes. Both refuse an oversized append before reserving or
copying bytes, and buffer growth stays within the selected ceiling. Encoding is
still one pass; physical publication, stored formats and recovery are unchanged
([#100 — Share bounded serialization buffers](https://github.com/dragginzgame/ic-memory/issues/100)).

Before the physical snapshot cut, the buffer cleanup alone reduced matched raw
Wasm probes by 1,227–1,235 bytes. The comparison uses unchanged
compiler/profile selections and the incoming selected lockfile. This is artifact
size evidence; it does not establish an IC instruction improvement.

The physical commit store retains one checksummed current snapshot. Its
`ICMESNAP` marker and required `current` field identify an incompatible physical
shape. The logical `ICMEMLED` / `ICMS` v1 ledger, permanent key/ID bindings,
retirement tombstones, schema metadata and checked generation remain intact.
The outer record ceiling is 64 KiB + 4 KiB; bounded decoding and corruption refusal
still precede allocation authority. IC execution supplies atomic stable-memory
commit and rollback; native backends retain their own transaction obligations.

**Consumer action:** replace `CommitSlotDiagnostic` with
`CommitSnapshotDiagnostic`, consume `CommitStoreDiagnostic.current`, and handle
`CommitRecoveryError::InvalidSnapshot { generation }`. The two-slot corruption
and ambiguity variants are removed. Do not fabricate a second empty slot in
application response DTOs. Canic's coordinated response/generator adoption is
tracked in [Canic #567 — Adopt single-snapshot recovery diagnostics](https://github.com/dragginzgame/canic/issues/567).

**Retained data:** existing two-slot images are rejected. There is no compatibility
reader, automatic initialization over incompatible bytes or migration engine.
Fresh installations can use the new format. Any retained installation needs its
owner's explicit disposition and, if preserving data, an application-owned
transition retaining every key/ID/tombstone and application recovery obligation.
This change does not authorize a reinstall, reset or deployment. See
[the current ledger contract](../current-ledger.md).

Bootstrap uses one internal validation/commit function while retaining the
pending-persistence proof. The owning runtime still persists the stable Cell
before confirming allocation authority. Request deserialization transfers its
already-validated key instead of rescanning and copying its text; authority,
reserved-namespace, schema, wire-shape and constructor error checks remain.
These changes are owned by
[#106 — One checksummed current ledger snapshot](https://github.com/dragginzgame/ic-memory/issues/106).

The physical cut reduces the five matched probes by 1,263–1,955 raw Wasm bytes
and 1,112–1,765 bytes after `wasm-opt -Oz`, compared with the incoming tree that
already contains the bounded writer. Steady-state records and native reopening
peak heap are roughly halved; this does not claim reclaimed stable pages or
lower IC instruction cost. See [matched qualification](../single-snapshot-qualification.md).
